## 阶段和分路交付

- 阶段为 `director-only`。先读完整确认文稿或真实转写、用户风格参考、本文件和插入镜头交接规范。
- 给Claude制作代码插片的唯一计划文件仍为 `edit/generated-video/<episode-id>/insert-shots.plan.json`。扩展字段按当前交接协议填写，不混入AI情景提示词、平台参数、审批状态或哈希。使用drafting时一并指向已归档的风格规范，不要求用户自己补绘画要求。
- 整份导演交付还包括全文分路判断和真实素材需求；选择AI情景时，同次交付独立 `AI视频生成提示词.md`。仅交代码JSON不能代替全文导演。
- 拍前可以分析全文、选原句和视觉意图；正式 `insertAt/enterSec` 必须在实录后绑定，没有真实时间证据不能填估算值冒充精确值。本轮只有参考片而无新一期正文时，只更新规则/模板，不擅自重做历史片。
- 不启动生图、首帧 OCR、RunningHub、Claude 会话、付费调用或渲染。用户把方案交给 Claude，本 Skill 不代替用户发送外部消息。
- 结构检查不证明语义、实录对齐、视觉效果或生成完成。每期方案仍供用户审阅，已有本期明确授权不重复询问。

## 全文导演判断

先明确全文主观点和论证顺序，再逐段选观众需要看的内容：

1. 真人：本人判断、信任、情绪、边界、行动号召，或其他画面不增加理解时保留主讲。
2. 真实素材：官方原文、真实操作、产品、场所或证据本身必须看见时使用，独立锁定来源和权限；政策原文不能用自写画面冒充官方页面。
3. 代码插片按语义选风格：数字、算账、对比、条款拆解和清单优先 `drafting`；需要可触实物、空间层次或人物关系搭景时用 `paper`；比喻、路径、关卡、游戏化表达用 `pixel`。新风格规范见[drafting](references/drafting-style.v1.json)，六种版式为 `ledger3/compare2/flow/clause/readout/stack`。
4. AI情景：具体工作动作、人物互动或环境体验能增加理解时使用。它是独立选项，不必先证明所有代码画风都无法表达；不能用AI画面补造真实客户、新闻或业务结果。

每期全文导演表必须明确AI情景“采用及原句/理由”或“不采用及具体理由”。采用时按[AI情景交接规范](references/ai-scene-handoff.v1.md)同次提供完整可复制视频提示词、生成与剪入长度、实录锚点、声音、安全区和回传位置。无新一期正文时只改规则，不编造本期镜头或视频词。

新对象式episode协议采用一主一辅：`primaryStyle` 默认drafting，`secondaryStyle`按需要选paper或pixel或省略；主风格占代码插片镜数至少70%。此比例只约束已选择的代码插片，不决定全片镜头数量，不计真人、真实素材及AI情景；`shots=[]`仍允许。内容不适合时先调整风格判断，不为达到比例制造插片。旧字符串episode方案按原合同读取，历史视频不迁移。`pixel`主题仍仅 `noir/blocks/mono`，paper/drafting用主色调说明。

用户要求更积极使用有帮助的插片：主动复核长真人段中的信息密度、比较和流程，不因旧“少量插片”、费用顾虑或2–8秒限制而机械压缩；也不设固定数量/间隔。候选不适配时重新判断可用的代码插片、AI情景或真实素材表达，不只写“不适配”就留下长空档。没有解释收益仍保留真人。

事实核验与画面选择独立。数字、倍数、价格、平台能力、因果和绝对化主张仍在本条事实锁中核对。插片只作说明，不能替代来源、实拍或实测，不能借画面升级未证实主张。

## 每镜写准

- 一个镜头解决一个认知目标，可以包含有关系的连续动作；交代对象、初态、变化、结果和阅读停留。
- `spokenLine` 保留实际说法；`title` 和3–5个中文节点只提炼原句已有意思（stack最多4个）。节点按画面左到右排列，每个 `label` ≤6个字符，Claude 原样排字。
- drafting镜头明确 `layout` 和 `assumption`；节点保留 `object`，并按需要写 `value/kind/source`。数字逐项给source，假设标清假设；clause逐字引用已读取原文并定位来源。存在source字符串不代表事实已核实，屏幕所有数字与公式仍须导演对照原声、事实锁及原文。
- `object` 只写看得见的物件和动作，不写“赋能、升级”等抽象命令。`flow` 写关系传递，原话是并列就明确并列，不能画成强制因果或前后工序。
- `ending` 写最后落定画面和读字停留；最后标签刚出现不能立刻切走。
- 标签绝对入点 = `insertAt + enterSec`。用音频/SRT/词级转写核对；只有句级 SRT 时听审窗口定位关键词，禁止平均分配时长冒充精准对词。
- `duration` 与交回 MP4 画面帧数/30一致。剪辑重排后重新绑定时点；不拉慢真人或冻结长段插片凑时长。
- `avoid` 每镜写明左下真人区、底部字幕区和禁用物件，直接交给 Claude，不能只放内部笔记。具体字段、避让起点和验收见[交接规范](references/code-insert-shots.v1.md)。
- 改写公开可见标题/标签时遵守项目文案双 Skill；原样搬运已确认文字不重复改写。审稿记录不加进用户 JSON。

## V9 与剪辑交接

- 同一对象有意义时连续承接，动作与阅读分开，语义不需要时允许自然收场。drafting长镜按6–8秒语义节点检查构图推进，超过8秒的同版式安排推近、横移或归纳；不机械硬切、不打断阅读，不改原声时长。
- 插片期间本条真人同步缩入左下小窗并连续播放，平滑交接，结束后回归。不得冻结人脸、移到右下或直接去掉主讲。
- Claude只生成插片本体，先读本期style/layout及风格规范；关键内容在最终合成尺寸仍须可读。字幕、真人小窗、转场、配乐和最终混音由Codex完成，不预先烘进插片。
- AI情景优先占据可用主画面，少留无意义外框；同时保留左下真人、独立字幕和AI情景标识，不能为了“全屏”裁掉关键动作。代码画面可标“示意动画”，但这不等于无需平台AI声明，不删除来源和原生AI标识。结尾卡仅在真实结尾窗口有表达收益时安排，不自动延长或覆盖原话。
- 保留拟音原轨，按口播清晰度和正常速度试听选择保留、压低或静音，避免与后补音效重复。本次授权允许静音，旧原生音效条款不能阻断新路线。
- Shotcraft 仅对真人/真实素材记录功能意图及完整原因，拍后按实录和保护区扫描相关库；不在任何代码插片或AI情景内部再叠加。具体效果选择不在拍前进行。

## 校验和回收

```text
完整文稿/实录 → 全文分路判断（必须写AI情景采用或不采用及理由）
→ 实录对词与时间绑定
→ 代码插片JSON → 用户交Claude → P01.mp4、P02.mp4…
→ 需要AI情景时，同次交AI视频提示词 → 用户生成 → A01.mp4、A02.mp4…
→ Codex逐镜验收并按实录剪入 → 左下真人、字幕、转场、混音 → 预览与用户确认
```

```bash
node skills/koubo-remotion-director/scripts/validate-insert-shots-plan.mjs --input <plan.json>
node skills/koubo-remotion-director/scripts/export-insert-shots-plan.mjs --input <plan.json> --repo-root <project-root>
```

交付前分别核对代码JSON、AI情景判断、所选AI镜头的完整视频词、真实素材需求与回传入口；未评估AI或需要却未交词，都不能称为导演交接完整。JSON工具只做结构检查，不能替代这项交接核对。

导出器仅写固定路径的一份JSON（新协议目录名取 `episode.id`），不覆盖已有文件，不调用模型。修订先读已有计划、保留版本记录再精准修改和复检，不能改期号掩盖同一期冲突。本期生成目录是交接目录，不建立第二套口播工程；已有素材入口可指向它，不能覆盖桌面同名项。

交回 `<shotId>.mp4`：1920×1080、30fps、画面时长等于 `duration`，建议放回同一期目录。全集仅作参考，不能代替逐镜文件。接片检查解码、规格/帧数、中文、节点时点、动作关系、读字停留、声音和避让区域；只返工失败镜头。当前规则更新不代表下一期已完成端到端验证。
