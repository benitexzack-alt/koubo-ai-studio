# 口播 RunningHub 图生视频批量执行

把已经通过质量验收的首帧和 `runninghub-image-to-video-prompts.v1.json` 一一写入 RHTV 视频节点。默认产物是“已配置、待用户运行”的画布，不是已生成视频。

## 职责边界

- 上游输入是已通过首帧质量门的批次和对应图生视频提示词清单；本 Skill 不重新导演、不改写原提示词、不重新生首帧。
- 浏览器写入、图片上传、节点创建、任务提交和付费生成是不同权限。每项只在用户明确授权的范围内执行。
- 未取得生成授权时，绝不点击“开始生成”，也不通过 RHTV Agent 对话创建工作流。
- 当前 RHTV 没有已验证的 CSV/JSON 原生批量导入入口。本 Skill 使用受控浏览器自动化逐节点填写。
- RHTV Agent 曾出现创建即提交和默认模型漂移；不得把 Agent 对话当作正式批量执行通道。

## 输入要求

至少取得：

- `runninghub-image-to-video-prompts.v1.json` 的绝对路径；
- 当前首帧批次或交接包路径；
- 目标 RHTV 画布 URL；
- 用户对本轮外部动作的明确授权范围。

每镜必须包含唯一 `sceneId`、`pairId`、图片文件名、提示词、提示词 SHA-256、时长和画幅。图片必须存在、哈希一致并已通过逐图质量检查。

## 执行模式

### 仅准备

只校验本地清单、图片、哈希和配对关系，不访问 RHTV。

### 画布填充

上传或选择已授权的图片，创建并配置节点，逐项回读，停在生成前。读取并严格执行 [references/rhtv-browser-procedure.md](references/rhtv-browser-procedure.md)。

### 批量生成

只有用户在看到画布填充回执后再次明确授权生成，才可点击运行。默认最多同时运行两个节点；每次运行前再次回读模型与参数，禁止自动重试。

## 固定门禁

1. 先核对目标画布和全部有效图片版本；修订图必须显式使用新文件名，旧图不得误绑定。文件名必须属于真实的 React Flow 图片节点；聊天输入区附件或临时上传提示不算可绑定画布素材。
2. 新任务先做一个代表节点校准。已有同一画布、同一 RHTV 界面版本的校准回执且状态为 `calibration-passed` 时可以复用。
3. 每个节点严格按以下顺序执行：
   - 创建“视频”节点并切到“首帧”；
   - 绑定对应图片引用；
   - 填入原始提示词；
   - 绑定后回读模型；若不是 `MiniMax H3` 才重新选择，若已经是则保留；
   - 最后设置 `2K`、清单时长和画幅；
   - 确认提示词优化处于 idle；
   - 回读节点文字并检查图片到视频节点的连线；
   - 停在“开始生成”按钮之前。
4. 图片绑定可能把模型重置为默认模型，这是已验证行为。因此不得只在绑定前锁模型；绑定后必须再次回读。若回读不是 `MiniMax H3`，重新选择模型和参数；若已经是 `MiniMax H3`，避免重复点击把模型面板意外收起，但仍需完成最终参数回读。
5. 每完成一个节点立即登记 sceneId、图片节点 ID、视频节点 ID、边 ID、提示词回读、模型和参数回读，不等整批结束才检查。
6. 全部节点通过后生成批量回执。没有用户生成授权时，回执必须明确 `taskSubmitted=false`、`videoGenerated=false`、`chargeObserved=false`。

## 失败与停止条件

- 图片、提示词、时长或 pair 映射不唯一；
- RHTV 中找不到指定图片的新版本；
- 文件只出现在聊天附件区，未形成可搜索、可连线的画布图片节点；
- 绑定图片后模型无法重新锁定为 MiniMax H3；
- 提示词回读与原文不一致；
- 节点参数不支持清单时长或画幅；
- 出现生成中、排队中、任务已提交或余额变化；
- 页面结构变化导致无法可靠定位控件；
- 任何节点被意外运行。

发生停止条件时，不继续创建后续节点，不重试付费动作，并保留已完成节点和现场回执。

## 完成用语

- 只完成本地校验：`批量清单已校验，尚未写入 RHTV。`
- 单节点校准通过：`校准节点已配置并回读通过，未生成视频。`
- 整批填充通过：`全部节点已配置并回读通过，停在生成前，待用户授权运行。`
- 获得授权并提交后：只能说 `任务已提交，等待生成结果与逐条验收。`
