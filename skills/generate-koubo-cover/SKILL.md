# 口播四宫格封面

## 必须交付的两阶段流程

一次封面任务必须严格分成两个阶段，不得合并：

1. `四宫格初稿`：先生成四张围绕同一主题、但表达和视觉方案明显不同的完整 `3:4` 候选封面，再按 `1、2、3、4` 排成 `2×2` 四宫格供用户选择。
2. `选中后精修`：等待用户明确选择一个编号，只精修所选单张，并交付无候选编号的最终 `1080×1440` PNG。

不得在用户选择前自行决定最终方案，不得把四宫格初稿称为最终封面，也不得在用户选中后顺带重做其余三个候选。

所有单张候选和最终单图必须是严格 `3:4`，默认 `1080×1440`。四宫格不得裁掉任一单张的标题、人物或画面边缘。

## 每次执行前

1. 读取项目 `AGENTS.md`、`project.md`、`knowledge/00-项目知识索引.md` 至 `knowledge/05-合规隐私与证据规则.md`。
2. 优先读取 `workflow/releases/<release>.json`；没有发布记录时，再读取用户给出的主题、文案、选题和正式视频。
3. 读取 [references/style-and-copy.md](references/style-and-copy.md)、[references/compliance.md](references/compliance.md)、[references/project-contract.md](references/project-contract.md) 和当期选定的 `workflow/style-library/*.md` 风格合同。
4. 判断当前处于 `四宫格初稿`、`用户选中后精修`、`用户否定重做` 中的哪一阶段。
5. 只处理用户明确指定的口播素材，不扫描无关目录。

## 阶段一：四宫格初稿

### 1. 建立事实底稿

只从最终口播、发布记录和已核验资料提取：

- 服务对象；
- 单一主题和单一结论；
- 真实痛点；
- 已验证数字与结果；
- 事实边界、禁止公开内容和行动引导。

没有证据的数字、效果、客户、收入、排名和平台结论一律删除。标题的钩子不能以牺牲真实性为代价。

### 2. 先提炼样本规律，再做原创转译

参考样本只用于抽象学习以下规律：

- 信息层级和标题占比；
- 真人、标题和主题物件的构图关系；
- 色彩、光影和缩略图对比；
- 标题句式、断行节奏和情绪张力。

不得把参考截图作为图生图输入或编辑目标，不得复刻样本人物、品牌、Logo、账号名、水印、受保护角色、独特文案、品牌界面或完整构图组合。提示词中不得出现“模仿某博主”“某账号同款”等要求。

### 3. 锁定共同品牌 DNA

四张候选必须先像同一个账号，再在结构和叙事上拉开差异：

- 共用一套账号主色、字体气质、真人处理和光线逻辑；
- 默认使用风格合同规定的墨蓝、电蓝、青蓝、暖金和白；
- 明暗与强调色比例可以变化，但不得变成四套互不相关的紫、绿、红、蓝模板；
- 颜色变化不计入候选差异，不能只换颜色或滤镜冒充不同方案。

### 4. 设计四个真正不同的候选

固定候选编号和宫格位置：

- `1`：左上；
- `2`：右上；
- `3`：左下；
- `4`：右下。

四张围绕同一主题，但必须分别设计：

1. 标题角度：问题、纠偏、数字步骤、行动或结果等不同表达；
2. 人物姿态：从同一条授权真实视频中选择不同时间点、自然表情和有效手势；
3. 构图重心：人物位置、标题位置和主要视觉流向明显不同；
4. 主题证据物或场景叙事：每张只保留一个与当期口播直接相关的原创语义中心。

任意两个候选必须在以上四项中至少三项不同。换同义标题、微调裁切、移动小装饰或改变颜色都不算有效差异。

### 5. 真实人物必须使用非生成式抠像

1. 只从用户本人或已获明确授权人物的真实视频、照片中选帧。
2. 使用非生成式人物分割生成透明 PNG；真人像素是锁定层。
3. 只允许裁切、等比缩放、位移、透明蒙版、非生成式调色、外侧轮廓光和投影。
4. 禁止用生成模型换脸、补手、改表情、改衣服、重绘五官或“统一人物风格”。
5. 禁止把原视频矩形窗口、圆角视频窗、椅背或大块原室内背景当作正式人物层。
6. 没有合格真人帧或抠像时，停止人物版正式生产，改做无人物方案或报告缺少输入；不得生成“像本人”的陌生人。

### 6. 区分版式证明和正式候选

背景资产只有两个等级：

- `layout-proof`：可使用代码生成的渐变、光路、几何节点和空框，只用于验证文字、人物占比和安全区，不得进入用户选择四宫格；
- `selection-grid`：必须使用与当期主题直接相关、`readiness=final` 的最终级原创背景，才允许进入独立审美复核和用户选择。

正式 `selection-grid` 禁止使用代码渐变、通用科技线条、空白 UI 卡、占位框或纯几何背景代替真实语义场景。常规正式生产应使用内置 `image_gen` 为四个候选分别生成背景，每张单独调用一次，并保存原始背景文件、提示词、生成方式和生成原因。

所有正式背景必须：

- 无人物、脸、手和身体轮廓；
- 无文字、乱码、Logo、品牌界面、水印和平台 UI；
- 不包含样本中的受保护元素；
- 只呈现与当期口播有关的原创商业、教学、工作流或本地叙事场景。

如果生图工具不可用、调用失败或背景未达到最终级，任务只能停在 `layout-proof`，不得拿占位背景继续交付四宫格。

### 7. 创建封面任务单

以 `workflow/cover-task-template.json` 为模板，在 `workflow/covers/` 新建带版本号的任务单。任务单是封面状态的唯一事实源，至少记录：

- 主题、事实底稿、风格合同和共享品牌色；
- 四个候选的标题、断行、副标题、高亮词和差异依据；
- 真实视频帧时间、人物透明抠图路径和非生成式处理方式；
- 版式、最终背景路径、提示词、生成原因和 `readiness`；
- 四张独立候选、四宫格、缩略图、灰度图、OCR 和复核报告路径；
- 事实、版权、人物身份、AI 标识、用户选择和拒绝状态。

四张独立候选图必须分别保存，四宫格不能代替单张候选文件。

### 8. 状态机

任务只允许沿以下路径推进：

```text
draft
→ layout-proof（可选，绝不能交付用户选择）
→ machine-ready
→ visual-review
→ grid-ready
→ selected
→ final-review
→ final-ready
→ approved
```

状态含义：

- `draft`：事实、文案、人物或背景方案仍不完整；
- `layout-proof`：仅完成占位版式证明；
- `machine-ready`：四张最终背景、真人抠像、单图、四宫格、尺寸和 OCR 等机器检查均齐全；
- `visual-review`：独立审美复核进行中，尚不可交付用户选择；
- `grid-ready`：独立审美门禁通过，可以展示四宫格；
- `selected`：用户已明确选择 `1、2、3、4` 中的一个编号；
- `final-review`：所选单张已精修，正在做最终独立复核；
- `final-ready`：最终 `3:4` 单图通过复核，待用户人工确认；
- `approved`：用户已确认最终封面；
- `rejected`：某一版本被用户否定或命中不可继续的硬失败，为终止状态。

不得从 `layout-proof` 直接跳到 `grid-ready`，不得由生成者自己把 `visual-review` 写成通过，也不得在 `selected` 之前生成正式最终图。

### 9. 渲染和机器验证

使用：

```bash
node skills/generate-koubo-cover/scripts/render-cover-set.mjs <cover-task.json> --mode grid
node skills/generate-koubo-cover/scripts/validate-cover-task.mjs <cover-task.json> --ocr
```

机器检查必须确认：

- 每张候选为 `1080×1440`，比例严格为 `3:4`；
- 四宫格严格按 `1、2、3、4` 排列为 `2×2`；
- 四张均显示对应编号，且没有裁切完整封面；
- 真人来自记录的真实帧，抠像含透明通道且没有被生成模型改写；
- 正式背景均为 `readiness=final`，不存在代码占位背景；
- 标题源字符串、OCR、缩略图和输出哈希已记录；
- 不含样本人物、Logo、水印、乱码、隐私、虚假结果和品牌混淆。

尺寸、OCR 和字段完整只代表 `machine-ready`，不能证明视觉已经通过。

### 10. 独立审美门禁

任务进入 `visual-review` 后，必须由未参与生成的独立复核者检查参考样本、当期风格合同、四张单图、手机缩略图、灰度图和人物蒙版。生成者的解释和自评分不能替代独立复核。

以下任一项命中即硬失败，直接退回修改，不进入分数放行：

- 原视频矩形窗口感、代码占位背景或通用科技线条充当正式背景；
- 人物残边、透明破洞、椅背残片，或脸、头顶、下巴、关键手势明显截断；
- 标题压脸、压手，三秒内看不出主题，手机缩略图不可读；
- 四张只靠换色形成差异，或不像同一账号；
- 出现样本人物、Logo、水印、品牌混淆、隐私、受保护元素或虚假主张。

没有硬失败时，每张按 100 分评分：

- 原创转译参考机制：20；
- 真人融合与边缘质量：20；
- 构图层级与单一视觉中心：15；
- 背景/证据物与主题关系：15；
- 手机缩略图可读性：15；
- 色彩、光影与品牌一致性：10；
- 工艺完整度：5。

只有同时满足以下阈值，才可把任务从 `visual-review` 改为 `grid-ready`：

- 每张总分不低于 `82`；
- 四张平均分不低于 `85`；
- 每张“原创转译参考机制”和“真人融合”均不低于 `15/20`；
- 每张“构图层级”和“主题关系”均不低于 `11/15`；
- 每张“手机缩略图可读性”不低于 `12/15`；
- 整组品牌一致性不低于 `85/100`；
- 整组结构差异不低于 `80/100`；
- 无任何审美硬失败；
- 复核报告、图片哈希、复核者和时间已经写入任务单。

向用户展示通过门禁的四宫格后立即停止，使用完成语：`四宫格初稿已生成，待你选择 1、2、3 或 4。`

## 阶段二：用户选中后精修

只有用户明确选择 `1、2、3、4` 之一后才进入本阶段。

1. 把选择编号、时间和用户反馈写入原任务单，将状态改为 `selected`。
2. 只围绕所选方案做针对性调整；保留用户未要求改变的标题角度、真人身份和核心构图。
3. 如需重新生成背景，只重做所选编号对应的背景；不得重做另外三个候选。
4. 使用 `final.overrides` 记录精修后的标题、色板、人物裁切或背景替换。
5. 渲染无候选编号的最终单图：

```bash
node skills/generate-koubo-cover/scripts/render-cover-set.mjs <cover-task.json> --mode final --selected <1|2|3|4>
node skills/generate-koubo-cover/scripts/validate-cover-task.mjs <cover-task.json>
```

6. 把状态改为 `final-review`，由独立复核者按同一套硬失败和单图分数阈值复查。
7. 只有尺寸严格为 `1080×1440`、已移除候选编号、标题与真人身份正确、版权和 AI 标识合规、缩略图可读且复核通过后，才改为 `final-ready`。
8. 用户人工观看并确认后，才把状态改为 `approved`。

用户确认前使用完成语：`最终封面已生成，待人工确认。`

## 用户否定与版本重建

当用户否定一组四宫格或最终图时：

1. 立即把当前任务版本改为 `rejected`；
2. 记录用户原话、拒绝原因、时间、旧图路径和图片哈希；
3. 保留旧任务和旧产物作为失败证据，不覆盖、不删除、不伪装成新稿；
4. 根据反馈重新分析标题、人物、构图、背景和工艺问题；
5. 新建递增版本号的任务单和输出目录，从 `draft` 重新开始；
6. 新版本仍须完整经过机器检查和独立审美门禁，不能因为“只是改稿”跳过。

`rejected` 是终止状态；不得在原任务上修改几处后重新标记为 `grid-ready` 或 `final-ready`。

## AI 与版权追溯

- 背景由生成模型制作时，如实记录模型、提示词、源文件和哈希，并按平台现行要求进行 AI 内容声明。
- 真人层不得进入生成模型；AI 背景不能制造真实客户、真实评价、虚假后台、收入或效果证据。
- 样本只保留为审美参考证据，不打包进 Skill，不默认提交 Git。
- 原始视频只读，不覆盖、不删除、不重命名。

## 输出与报告

按 [references/project-contract.md](references/project-contract.md) 保存并报告：

- 四张独立 `1080×1440` 候选；
- 一张完整 `2×2` 四宫格预览；
- 用户选中后的最终 `1080×1440` 封面；
- 受版本控制的任务单；
- 抽帧、人物抠图、背景原图、OCR、缩略图、灰度图、哈希和独立复核证据；
- 使用的真实帧时间、背景生成方式和 AI 标识建议。

不得把“生成成功”或“审美门禁通过”写成“封面点击效果已验证”。点击率、完播率和发布表现只能由真实发布数据判断。
