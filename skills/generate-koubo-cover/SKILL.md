# 口播四宫格封面

## 核心产物

执行两个不可跳过的阶段：

1. 先生成一张 `2×2` 四宫格预览，内含编号 `1、2、3、4` 的四张完整 `3:4` 候选封面。
2. 等待用户明确选择一个编号，再精修所选方案并输出无候选编号的最终 `1080×1440` PNG。

不得在用户选择前自行决定最终方案，不得把四宫格初稿称为最终封面。

## 每次执行前

1. 读取项目 `AGENTS.md`、`project.md`、`knowledge/00-项目知识索引.md` 至 `knowledge/05-合规隐私与证据规则.md`。
2. 优先读取 `workflow/releases/<release>.json`；没有发布记录时，再读取用户给出的主题、文案、选题和正式视频。
3. 读取 [references/style-and-copy.md](references/style-and-copy.md)、[references/compliance.md](references/compliance.md) 和 [references/project-contract.md](references/project-contract.md)。
4. 判断当前处于 `四宫格初稿` 还是 `选中后精修` 阶段。
5. 只处理用户明确指定的口播素材，不扫描无关目录。

## 阶段一：生成四宫格初稿

### 1. 建立事实底稿

只从最终口播、发布记录和已核验资料提取：

- 服务对象；
- 单一主题和单一结论；
- 真实痛点；
- 已验证数字与结果；
- 事实边界、禁止公开内容和行动引导。

没有证据的数字、效果、客户、收入、排名和平台结论一律删除。

### 2. 设计四个真正不同的候选

固定候选编号和宫格位置：

- `1`：左上；
- `2`：右上；
- `3`：左下；
- `4`：右下。

四张必须围绕同一主题，但在以下五项全部形成明显区别：

1. 标题表达：分别采用问题、纠偏、数字步骤、结果或行动等不同角度；
2. 人物表情：从同一条授权真实视频中选择四个不同时间点和自然表情；
3. 画面构图：人物位置、标题位置和视觉重心不得相同；
4. 背景氛围：每张只使用一个不同的原创场景隐喻；
5. 颜色搭配：四组主色与强调色组合必须可辨。

不得用同一封面只换颜色冒充四个方案。不得用生成模型改脸、补手、改变服装或伪造人物表情。

### 3. 创建封面任务单

以 `workflow/cover-task-template.json` 为模板，在 `workflow/covers/` 创建任务单。保存四个候选的：

- 标题、断行、副标题和高亮词；
- 真实视频帧时间与期望表情；
- 版式、色板、背景氛围和原创隐喻；
- 背景提示词、源素材路径和输出路径；
- 事实、版权、人物身份和 AI 标识状态。

任务单是封面状态的唯一事实源。四张独立候选图必须分别保存，四宫格不能代替单张候选文件。

### 4. 选择并记录背景方式

常规正式生产优先调用内置 `image_gen`，分别生成四张不同背景。每张单独调用一次，不用一个提示词生成四个近似变体。

也可以在首轮流程验证、纯抽象科技背景或需要完全可复现的版式中，明确选择渲染脚本的确定性原创背景。两种方式都必须在每个候选的 `background.mode` 和 `background.generationReason` 中如实记录：

- `generated`：四张背景分别由 `image_gen` 生成；必须保存每张背景文件路径，并设置 AI 生成标识；
- `deterministic`：由脚本生成原创渐变、光路、节点和几何图形；必须说明选择原因，不能伪称 AI 生图失败。

只有真实发生工具不可用或调用失败时，才可以把 `generationReason` 写为失败兜底，并保留失败证据。无论使用哪种方式，背景都必须满足：

- 无文字；
- 无人物、脸、手和身体轮廓；
- 无 Logo、品牌界面、水印和平台 UI；
- 与当期主题有关的原创商业、教学、工作流或本地叙事背景。

### 5. 合成与验证

使用：

```bash
node skills/generate-koubo-cover/scripts/render-cover-set.mjs <cover-task.json> --mode grid
node skills/generate-koubo-cover/scripts/validate-cover-task.mjs <cover-task.json> --ocr
```

必须检查：

- 每张候选为 `1080×1440`；
- 四宫格为 `2×2`，顺序严格为 `1、2、3、4`；
- 四张都显示对应编号；
- 主标题、人物和一个核心信息在手机缩略图下可读；
- 人物来自真实帧且未被生成模型改写；
- 不含样本人物、Logo、水印、乱码、隐私和虚假结果。
- OCR 报告已经保存到任务单声明的证据路径；OCR 只是辅助提醒，不能替代标题源字符串核对和人工缩略图检查。

向用户展示四宫格后停止，使用完成语：`四宫格初稿已生成，待你选择 1、2、3 或 4。`

## 阶段二：用户选中后精修

只有用户明确选择 `1、2、3、4` 之一后才进入本阶段。

1. 把选择编号、时间和用户反馈写入原任务单，将状态改为 `selected`。
2. 只围绕所选方案做针对性调整；保留用户未要求改变的标题角度、真人身份和核心构图。
3. 如需重新生成背景，只重做所选编号对应的背景；不要重做另外三个候选。
4. 使用 `final.overrides` 记录精修后的标题、色板、人物裁切或背景替换。
5. 渲染无候选编号的最终单图：

```bash
node skills/generate-koubo-cover/scripts/render-cover-set.mjs <cover-task.json> --mode final --selected <1|2|3|4>
node skills/generate-koubo-cover/scripts/validate-cover-task.mjs <cover-task.json>
```

6. 完成尺寸、文字、人物、版权、缩略图和 AI 标识复查后，将状态记为 `final-ready`。
7. 用户人工观看并确认后，才把状态改为 `approved`。

最终图不得保留四宫格候选编号。用户确认前使用完成语：`最终封面已生成，待人工确认。`

## 人物身份硬规则

- 只使用用户本人或已获明确授权人物的真实视频帧、照片或透明抠图。
- 把真人层视为锁定像素；只允许裁切、等比缩放、位移、蒙版、非生成式调色和外侧投影。
- 不把合成后的真人图再次交给模型“统一风格”。
- 没有可用真人帧时，生成无人物版或说明缺少输入；不得生成“像本人”的陌生人。

## 样本与版权硬规则

- 只抽象学习信息层级、构图比例、色彩逻辑和标题句式。
- 不把参考截图作为编辑目标或图生图复刻素材。
- 不在提示词中写“模仿某博主”“某账号同款”。
- 不复制样本人物、姿势组合、Logo、品牌界面、账号名、水印、独特文案或完整版式组合。
- 原始样本不打包进 Skill，不默认提交 Git。

## 输出与追溯

按 [references/project-contract.md](references/project-contract.md) 保存：

- 四张独立候选；
- 一张四宫格预览；
- 用户选中后的最终封面；
- 受版本控制的任务单；
- 抽帧、OCR、缩略图和质检证据。

报告最终路径、使用的真实帧时间、背景生成方式和 AI 标识建议。不得把“生成成功”写成“封面效果已验证”；发布表现只能由真实数据判断。
