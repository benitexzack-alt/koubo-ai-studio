# V9.1 Shotcraft 自动匹配与验收经验闭环

## 目标

V9.1 让导演在拍摄后以实录口播、当前主画面和已验收素材为输入，自动检索 Shotcraft 锁定快照的全部 157 张卡和 214 个样式，然后按语义、素材类型、主画面、时长、能量和历史验收记录排序。用户不需要手动浏览卡库。

## 硬边界

- 实录录音是字幕和效果文字的唯一正文；拍摄前文稿只是对照。
- 全库 157 张都参与检索，但当前只有注册表中 5 张具备本地候选组件。其余 152 张只能进入适配候选，不能冒充已落片效果。
- 如果未适配卡明显更符合语义，本轮保留原画面并列入适配队列，禁止用次优现成效果硬套。
- `paper-editorial` 和 `generated-video` 主画面内不选 Shotcraft；它只能辅助 `speaker` 和 `real-evidence`。
- 不设最低应用数量。没有合适效果时，全部 `not-needed` 是合法结果。
- 经验复用仍然必须经过本条低清候选片和用户完整观看；系统不自动授权正式渲染或发布。

## 实际流程

1. 重建并校验全库能力索引：

   ```bash
   node skills/koubo-shotcraft-library/scripts/build-card-capability-index.mjs
   ```

2. 在 `postshoot-rebound` 阶段从 `templates/auto-match-request.v1.template.json` 建立本条请求，绑定实录字幕、注册表、全库索引、经验账本和组件哈希。
3. 自动检索与决策：

   ```bash
   node skills/koubo-shotcraft-library/scripts/match-director-effects.mjs \
     --request <auto-match-request.json> \
     --selection <director-selection.json> \
     --receipt <auto-match-receipt.json> \
     --lookup <experience-lookup-receipt.json> \
     --repo-root .
   ```

4. 渲染候选片后，应用回执必须证明所选组件确实出现在同一份候选片中。
5. 用户完整观看后，从 `templates/experience-decision.v1.template.json` 记录每个已应用 beat 的 `accepted` 或 `rejected`，并写入账本：

   ```bash
   node skills/koubo-shotcraft-library/scripts/record-experience.mjs \
     --decision <experience-decision.json> \
     --receipt <experience-write-receipt.json> \
     --repo-root .
   ```

## 经验晋级

- 同一语境的一次明确验收：下次作为“已验收案例”优先候选，但仍需本条预览。
- 同类语境在至少两个不同任务中验收成功：才晋级为“可复用规则”。
- 同一语境的最新否决：覆盖旧的通过记录，阻断精确复用。
- 注册表或组件哈希改变：旧案例降为过期证据，不参与直接复用。

## 回执

V9.1 每条新片必须保留 `shotcraftAutoMatchRequest`、`shotcraftAutoMatchReceipt`、`shotcraftExperienceLookupReceipt`、`shotcraftSelectionPlan`和 `shotcraftApplicationReceipt`。用户确认候选片后，还必须保留 `shotcraftExperienceWriteReceipt`。缺任意一项都不得晋级下一阶段。
