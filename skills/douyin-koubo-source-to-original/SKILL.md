# 口播源头拆解与原创合成

本 Skill 处理的是现有链路缺少的一段：不是把来源摘要后直接写稿，而是先看清一条口播怎样把观众的现实矛盾、证据、反转、解释和结尾组织起来，再决定哪些功能可以迁移、哪些内容绝不能迁移。

## 真实目标

服务 `超哥AI创业记` 的长期内容主线：通过持续、可信的内容让兰州及本地企业认识到讲述者能把 AI 技术翻译成业务问题、验收责任与可行动判断。它可以为未来 AI 落地、应用陪跑、企业知识库、AI 培训和 GEO 建立信任入口，但不得把这个目标写成已完成的客户结果、服务能力或商业承诺。

## 不是做什么

- 不是“看到参考视频就仿写”的工具。
- 不是按播放、点赞或封面点击率给结构打因果分的工具。
- 不是把外部作者的案例、收入、客户、实操过程改写成超哥经历的工具。
- 不是实操教程生成器；没有用户真实操作、屏幕、输入、卡点、输出和验收时，只能产出研究卡和待试验清单。
- 不是公开稿、分镜、成片或发布的放行器。

## 输入准入

1. 外部参考必须有完整转写，且标明作者、来源完整度、允许用途和事实边界。
2. 账号样本必须有完整确认稿或真实录音转写；仅有后台指标不能入样。
3. 数据只作为描述性表现切面。指标口径、统计窗口或当前性不明时，必须显式标记，不能推出“这个钩子一定好”。
4. 每轮分析都必须读取账号主线、声音档案、最近六条与当前账号学习卡。
5. 任何拟进入公开稿的事实仍须使用独立证据核验。

## 六样本自动化准入

第一轮固定为三条账号样本与三条完整外部参考：

- 账号样本分别覆盖：播放与本地转化、封面点击、点赞认同。
- 外部样本至少两条来自姜胡说，另一条来自不同创作者。
- 每条必须有一张人工可审的“口播机制卡”：钩子、观众矛盾、反转、证据方式、回扣、可迁移功能、不可迁移内容，以及为什么服务或不服务账号主线。

运行：

```bash
python3 <project-root>/skills/douyin-koubo-source-to-original/scripts/validate_pilot.py \
  <project-root>/notes/2026-08-19-口播源头拆解六样本-自动化准入卡-v1.json
```

状态含义：

- `blocked`：样本缺失、来源不完整、样本配比错误、结构卡不完整，或出现试图直接生成公开稿的配置。
- `ready-for-manual-review`：六样本资料完整，等待用户逐条确认结构拆解。
- `ready-for-analysis-automation`：六条都经用户确认；仅允许每日来源分类、机制卡草案和选题/钩子候选。

## 固定工作流

```text
日常抓取与来源完整度核验
-> 本 Skill：单条机制卡
-> 本 Skill：跨源功能矩阵与账号主线筛选
-> 用户确认问题、三个钩子与一个提纲骨架
-> source-essence-synthesis
-> content-brain-gate
-> humanizer-zh
-> humanize-koubo-script
-> 用户本人朗读确认
```

本 Skill 是 `source-essence-synthesis` 的研究前置件，不替代后者的认知节点、论证链、事实纠偏和提纲覆盖校验。用户没有选定问题、钩子和提纲前，禁止进入完整稿。

## 每日自动化的允许输出

在 `ready-for-analysis-automation` 后，每日可以输出：

1. 来源资格清单和不完整来源的补料要求。
2. 每条来源的口播机制卡草案。
3. 与六样本相比的结构相似点与过度模仿风险。
4. 最多三个服务账号主线的选题候选，每个候选只给现实场景、核心矛盾、本人证据缺口和三个钩子方向。

每日自动化不得输出：完整公开稿、虚构案例、工具实操步骤、收益/获客承诺、自动发布或制作指令。

## 用户确认门

六条样本不是“训练完成”的同义词。每条机制卡都需用户确认以下两件事：

1. 对“它为什么能成立”的解释是否准确。
2. 标出的可迁移与不可迁移边界是否正确。

六条确认后才开放分析自动化。随后新主题仍需用户选择钩子和提纲，才进入既有的公开内容门禁。
