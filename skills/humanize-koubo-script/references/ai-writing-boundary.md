# 口播 AI 味边界与真人化改写规则

> 用途：给公开口播文案建立稳定的“AI 味”识别边界。
> 核心定义：AI 味不是“AI 写过”，而是文本暴露了模型生成过程，而不是真人在现场判断、取舍和说话。

## 一、基本判断

一段口播出现 AI 味，通常不是因为用了某个词，而是因为这句话的功能不属于真人口播现场。

交付前先问：

1. 这句话是在讲事情，还是在讲“我准备怎么讲事情”？
2. 这句话删掉以后，信息、判断或情绪推进会不会减少？
3. 这句话有没有具体的人、动作、场景、后果？
4. 这句话是不是为了显得稳、完整、有结构才出现？
5. 这句话像不像真人临场会说的话？如果更像审稿附录，应移到事实锁或删除。

## 二、六类高频 AI 味

### 1. 自我说明型

典型句：

- “我今天不讲……”
- “我想讲一个……判断”
- “这不是一句……标题”
- “接下来我会从几个方面讲”

问题：它在解释写作意图，不是在讲事情。

改法：删掉自我说明，直接进入判断。

```text
坏：我想讲一个更现实的判断。
好：接下来十年，不是所有人一起变好，也不是所有人一起变差。
```

### 2. 防御性边界型

典型句：

- “这不是预言”
- “这不是吓人的标题”
- “不是说普通人一定完了，也不是说学会 AI 就一定翻身”

问题：边界需要保留，但连续防御会让正文像审稿报告。

改法：把边界嵌进判断。

```text
坏：这不是预言。
好：它不是一个确定答案，而是一个分岔。
```

### 3. 万能转场型

典型句：

- “关键在于一件事”
- “真正的问题在后面”
- “这也解释了为什么”
- “说到这里，你可能会问”

问题：这些句子常被模型用来拼接段落。真人转场通常带着具体对象。

改法：让转场直接指向例子、场景或动作。

```text
坏：关键在于一件事。
好：你看客服这个例子，就能看出这个分岔。
```

### 4. 抽象评价型

典型句：

- “更现实的判断”
- “更重要的能力”
- “真正值得看的地方”
- “长期行动方向”

问题：抽象词没有立即接具体动作，就会空。

改法：抽象判断后必须跟具体的人、动作、场景或后果。

```text
坏：这是更重要的能力。
好：你能不能看出 AI 给的方案哪里不适合这个客户。
```

### 5. 资料插入型

典型句：

- 突然插入“同样是客服 AI……”
- 突然插入论文、数据、机构名，而没有说明它解决当前哪一个问题

问题：来源抢了口播主线，像从资料库搬进来的例子。

改法：先说明为什么用这个例子。

```text
坏：同样是客服 AI……
好：这个分岔怎么理解？看客服最清楚，因为客服既有标准问题，也有新人练判断的过程。
```

### 6. 机械完整型

表现：

- 背景、来源、机制、边界、行动全部铺满；
- 每段都正确，但整体不像人在说话；
- 为了保留所有点，牺牲当下观众最需要先听懂的那一点。

问题：口播不是资料完整优先，而是观众认知变化优先。

改法：每段只保留一个当下功能：冲突、纠偏、机制、例子、判断或动作。

### 7. 审稿备注泄漏与假性思考型

典型句：

- “这里说的是公布的产能，不是实际销量”；
- “公开报道里……也是现场对标口径”；
- “我在现场看到……讲解中提到”；
- “我又把这个词重新看了一遍”；
- “我更愿意把它理解成”。

问题：这些话分别属于事实锁备注、来源标签、重复归因和模型生成的思考支架，不是观众此刻需要听的信息。

改法：来源和口径先留在事实锁；正文直接说事实、场景或判断。确实必须说的边界，只保留对当前结论有影响的那一层，不念审稿附录。

## 三、真人化改写原则

### 1. 现场入口

从观众正在经历的误判、动作或场景进入，不从“我要讲什么”进入。

```text
坏：我今天想讲 AI 对普通人的影响。
好：你现在可能还在纠结要不要学工具，但公司已经在拆岗位里的任务了。
```

### 2. 明确取舍

真人会告诉观众先看哪里、先别看哪里。

```text
先别看职业名称，先看你每天卖出去的那部分能力。
```

### 3. 具体动作

把抽象能力落成可观察动作。

```text
坏：提升判断力。
好：看出 AI 给的方案哪里不适合这个客户。
```

### 4. 自然边界

边界不做连续免责声明，嵌入判断里。

```text
坏：这个数据不能外推到所有人，也不代表所有行业。
好：这个数据不能外推到所有人，但它提醒我们，入门执行任务正在先变。
```

## 四、执行清单

每次交付公开口播稿前，必须输出 `ai_boundary_review`：

- `self_explanation_removed`：是否删除或改写自我说明型句子；
- `defensive_boundary_embedded`：是否把防御性边界嵌入判断；
- `generic_transitions_replaced`：是否替换万能转场；
- `abstract_claims_grounded`：抽象判断是否落到人、动作、场景、后果；
- `source_insertions_contextualized`：来源和案例是否说明了为什么出现；
- `mechanical_completeness_reduced`：是否把“完整优先”改为“观众认知变化优先”。

如果任一项为 `false`，必须在报告里说明原因；没有正当原因时不得标记为通过。
