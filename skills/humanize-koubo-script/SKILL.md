# 口播文案去 AI 味

把上游 `humanizer-zh` 当作模式检查器，不把它当作事实生成器。目标是让稿子更像用户本人能自然说出口的话，同时保住口播的事实、证据、钩子和行动目标。

## 项目根目录

从当前工作目录向上查找同时包含 `AGENTS.md`、`knowledge/` 和 `skills/` 的目录，将它记为 `<project-root>`。项目文件全部从该根目录相对定位。

## 必读

执行前读取：

1. `<project-root>/AGENTS.md`
2. `<project-root>/knowledge/02-个人事实与公开边界.md`
3. `<project-root>/knowledge/05-合规隐私与证据规则.md`
4. `<project-root>/knowledge/06-选题脚本与风格规范.md`
5. `<project-root>/knowledge/14-超哥口播声音档案.md`
6. `<project-root>/skills/content-brain-gate/SKILL.md` 及其指定的内容门禁规则。
7. 本条内容门禁卡与最近一次机器校验报告
8. 待处理稿件的事实来源、证据表和用户已确认版本

必须读取 `${CODEX_HOME:-$HOME/.codex}/skills/humanizer-zh/SKILL.md` 的当前版本，将其只用于发现 AI 写作模式。文件缺失或无法读取时状态为 `blocked`，不得继续交付文稿。上游规则与本 Skill 冲突时，以本 Skill 和项目事实边界为准。

## 使用门槛

以下场景必须自动使用：

- 生成或修改将要公开的口播标题、钩子、正文、转场、金句、结尾或行动引导；
- 对口播稿做续写、压缩、扩写、润色、重组、去 AI 味或口语化；
- 把资料、转写、采访、项目事实或参考内容整理成新的公开口播稿；
- 审查空话、套话、机械结构、本人声音、留存风险或划走风险。

仅做逐字转写、字幕时间轴、官方原文摘录或用户已确认原话的原样搬运时，不改写文本；一旦把这些内容重新组织为公开口播稿，立即恢复本 Skill。

本项目的公开口播从 `ready-for-draft` 形成实际稿件后，必须执行一次本 Skill；任何后续实质改稿都必须重新执行并生成绑定新稿哈希的报告。若内容门禁仍是 `blocked` 或只有 `ready-for-outline`，先修来源、选题、机制和重复问题，不得用去 AI 味改写掩盖上游缺陷。

“留存风险审稿”是固定步骤，不再是可选分支。执行前从稿件、选题卡或用户要求中确认目标观众、首要行为目标、当前证据和不可改动项；无法确认时只标风险，不直接改写。

以下内容默认不改：

- 实录转写及字幕时间轴；
- 用户已经确认的原话；
- 官方原文、直接引语和法律合规口径；
- 数字、日期、人名、地名、产品名和证据等级；
- 已锁定的钩子、核心结论、金句和唯一行动引导。

如确需改动上述内容，先列出建议和影响，等待用户确认。

## 工作流

### 1. 建立事实锁

先从原稿和证据中列出：

- 不可新增的事实、经历、案例、客户反馈和结果；
- 不可改写强度的数字、来源、个人观点、合理推断和未确认事项；
- 必须保留的钩子、主张、证据载体、适用边界和行动引导；
- 用户真实口吻样本。优先使用用户确认稿或真实口播转写，不模仿无意义的“嗯、啊、然后”。
- 本条与 `knowledge/14-超哥口播声音档案.md` 的一致项，以及与最近六条相比必须保持的新表达。

事实锁没有建立时，只做问题标注，不直接重写。

### 2. 做留存风险审稿

每次处理公开口播文案都必须执行。把模型判断写成“预测风险”，不得冒充真实留存数据或平台结论。

逐句或逐段检查，最多指出 3 个高风险节点，不为凑数量强行挑错。风险原因只能落在可解释的内容机制上：

- 观众利益或问题不清楚；
- 抽象、重复、信息增量不足；
- 转场突然，叙事从观众问题滑向作者自述；
- 单句负载过高、口播难懂或缺少必要铺垫；
- 主张缺少证据承接，或表达强度超过证据；
- 文字与预定画面重复，继续口述会拖慢节奏。

先判断问题应由文案、画面还是删减解决。画面能够更准确解决时，保留原意并提出画面建议，不为追求刺激强改文案。

每个高风险节点按以下格式输出：

1. 原句或位置；
2. 预测风险与理由；
3. 保守版、直接版、生动版三个候选；
4. 每个候选的事实差异检查；
5. 推荐版本和推荐理由。

三个候选必须使用同一事实底座，不新增人物、经历、数字、案例、结果、因果或收益，不把合理推断改成事实。生动版只能改变表达和节奏，不能虚构悬疑、冲突、客户反馈或生活细节。候选可能改变钩子、主张强度、证据载体或行动引导时，只给建议，等待用户选择后再并入完整稿。

没有高风险节点时明确写“未发现需要强改的高风险句”，不得为了显示能力而重写。

### 3. 只找真实存在的问题

重点检查：

- “时代浪潮、重要意义、全新格局”等抽象大词；
- “专家认为、行业报告显示”等没有具体来源的归因；
- 连续使用“不是……而是……”“第一、第二、第三”等机械结构；
- 每句长度、语气和落点都相同；
- 书面连接词、重复总结、空泛乐观结尾和聊天机器人客套话；
- 为了显得具体而补入原文和证据中不存在的细节。

不要因为某个结构在上游清单里出现就机械删除。短视频中有效的反问、对比、三点清单和金句可以保留，只要它们承担真实的信息或节奏功能。

### 4. 小范围重写

- 优先修改最有 AI 味的句子，不整篇推倒重写。
- 用用户已经提供的事实替代空话；没有事实时删除空话，不编造细节。
- 保留兰州、甘肃、本地老板等真实定位，但不为“接地气”强加方言、网络梗或粗口。
- 允许长短句变化和自然停顿，确保用户能一口气说完。
- 第一人称只用于用户真实经历或明确观点，不能凭空增加“我见过”“我客户”“上周和朋友聊过”。
- 不为了去 AI 味故意制造错别字、逻辑跳跃或无意义的混乱。

### 5. 做事实差异检查

逐句对比改写前后：

- 新增数字、日期、人物、机构、案例、反馈、结果或经历：失败，撤回。
- 将未验证改成肯定、将个人观点改成事实、将作者主张改成项目结论：失败，撤回。
- 删除必要的不确定性、适用边界、风险说明或来源：失败，补回。
- 改变核心观点、钩子含义、证据载体或行动引导：先征得用户确认。

事实保真度必须为 10/10，否则不交付改写稿。

### 6. 做口播朗读检查

检查：

- 大声读是否自然，是否出现连续长句和绕口词；
- 每句话是否只有一个主要意思；
- 停顿位置是否符合中文口语；
- 开头是否仍能迅速识别受众和问题；
- 中段是否有真实证据或演示；
- 结尾是否只保留一个动作。

## 输出格式

默认输出：

1. 留存风险审稿：最多三个真实风险节点及保守版、直接版、生动版候选；没有高风险节点时写明理由。
2. 精修后的完整口播稿。
3. 仅列出有实质影响的修改，不做流水账。
4. 事实保真检查：新增事实、删除事实、口径变化、待用户确认项。
5. 五项评分：直接、口语、节奏、本人感、事实保真，各 10 分。
6. 上游状态复核：来源资格、最近六条差异、机制卡和内容门禁状态是否仍成立。
7. `copy_review` 机器报告：按 [文案双 Skill 执行报告格式](references/copy-review-report-schema.md) 写入 JSON 文件，并让内容门禁校验器验证。
8. 发布包装：每份完整口播稿必须同时附带一个抖音主标题、两个备选标题和一份可直接复制的全中文 `3:4` 封面提示词。标题必须经过事实差异检查；封面提示词必须明确标注为“真人截图合成”，默认使用用户上传的当期成片真人截图作为唯一人物，保持五官、表情、衣服和姿态不变，不得让模型重画或虚构用户。提示词至少写清精确封面文字、构图、人物位置、真实主题元素、光线、色彩、画幅和禁用元素。

需要对比时，再提供“原句 → 改句 → 原因”。未经要求，不同时给出多个大版本，避免用户无法判断最终稿。

发布包装只能使用中文。缺少抖音标题或封面提示词时，状态为 `incomplete-delivery`，不得把正文单独称为完整口播稿。

留存风险审稿只给高、中、低风险和具体理由，不给伪精确的完播率、划走概率或提升百分比。用户未选择候选前，不把可能改变主张或结构的版本自动并入完整稿。

## 硬边界

- 不新增任何原稿和证据中不存在的具体细节。
- 不把“更具体”误解为“编一个例子”。
- 不自动删除钩子、金句、反问、对比、三点清单或行动引导。
- 不替用户虚构口头禅、情绪、朋友、客户、收入、效果或亲历。
- 不把模型预测的划走风险说成真实观众行为，不承诺提高完播、留存、涨粉或成交。
- 不为了制造钩子虚构悬疑、对立、损失、因果、案例或数据。
- 不用标题或封面制造正文没有回答的问题，不把推断包装成事实，不用“AI泡沫已破”等未经正文和证据支持的强结论。
- 不用“降低检测率”作为目标；目标是事实准确、自然可说、符合本人表达。
- 不在事实、选题和结构尚未锁定时自动改写；但本项目每条准备公开拍摄的口播，在进入 `ready-for-production` 前必须执行一次并保留事实差异检查。
- 不接受手填 `humanize_passed: true` 代替执行报告；报告缺失、Skill 哈希过期或稿件哈希不匹配时必须重新执行。
