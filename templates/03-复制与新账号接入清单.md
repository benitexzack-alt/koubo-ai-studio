# 复制与新账号接入清单

## 两种复制模式

### A. 协作同一个账号

适合另一台机器继续服务“超哥 AI 创业记”。可以使用仓库内账号战略、公开边界和声音档案，但仍需通过授权渠道取得未进 Git 的原片、当期脚本、个人知识库现行规则和 API Key。

固定顺序：

```bash
git clone <仓库地址>
cd <仓库目录>/remotion
npm ci
cd ..
node tools/setup-koubo.mjs --dry-run
node tools/setup-koubo.mjs
node tools/doctor-koubo.mjs
node tools/test-portable.mjs
```

安装完成后复制 `.env.example` 为 `.env`，只在接收机器本地填写密钥。不要通过 Git、聊天记录或截图传递密钥。

### B. 用于另一个账号

仓库可以复用技术流程、Skill、Remotion 组件、门禁结构和质检工具，但不得直接复用“超哥”的个人身份和事实。

开始写稿前至少替换并人工确认：

1. `knowledge/01-账号战略与事业主线.md`；
2. `knowledge/02-个人事实与公开边界.md`；
3. `knowledge/14-超哥口播声音档案.md`，并按新账号重命名；
4. 最近六条已发布、已拍摄或已确认内容台账；
5. `project.md` 当前目标、服务对象和账号阶段；
6. `assets/素材台账.csv` 中的来源、授权和实际相对路径。

替换完成前，内容状态保持 `blocked`。不得把示例中的兰州、甘肃、38 岁、客户经历、证书或创业经历改个名字后直接发布。

## Git 不包含的内容

- 原始视频和代理媒体；
- 转写缓存、中间导出和正式成片；
- `.env`、API Key 和本机工具绝对路径；
- 个人知识库现行规则与当期私有脚本；
- 本地字体和未确认可再分发的素材。

这些缺失项不应从原制作机目录硬复制。应通过双方确认的授权渠道取得，并在接收机器上单独存放。

## 不影响原机器的保证边界

- `tools/setup-koubo.mjs` 只为缺失的项目 Skill 创建符号链接；发现同名不同来源时整次停止，不覆盖、不移动、不删除。
- `tools/doctor-koubo.mjs` 只读取文件状态和命令位置，不读取或显示密钥内容。
- 项目内规则快照不会写回个人知识库；检测到个人知识库时，个人知识库现行版继续优先。
- 原始素材保持只读，转写脚本只生成临时音频；没有 `--confirm-upload` 时不会访问 ElevenLabs。
