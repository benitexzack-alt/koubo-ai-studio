# V9 导演流程升级审计与试点边界

## 用户问题

1. 真实素材讲解时，右下角人物小窗被抖音作者头像遮挡。
2. 纸艺首帧提示词缺少机器可检查的布局合同，生成端反复试图满足像素级自然语言要求，拖慢交付。
3. Shotcraft 候选库虽然已存在，但导演选择、实录重绑、组件落片和候选 QA 之间没有完整证据链。
4. 文稿确认、提示词交接、外部生成、素材接收、实录重绑、小样、正式渲染和发布包的顺序没有统一状态机。

## V9 改动范围

- 建立抖音 `16:9` 横屏内容在信息流中的平台覆盖安全区；人物使用固定安全槽，转场只在槽内改变透明度和缩放。
- 纸艺首帧增加归一化内容安全区、字幕保留区、逐物件组和逐标签纸面矩形；安全边界为硬门，组内矩形只作宽区构图指导，不要求生成模型像素级复刻。几何不完整时在生成前阻断。
- V9 首帧先生成一张最具代表性的样图，失败即停且禁止自动重试；只有样图通过并经人工确认后才进入余图。若无字基础图已通过、仅确定性写字或 OCR 失败，复用原图修文字链，不重新消耗生图。
- 导演固定输出三套独立交接包：纸艺首帧、RunningHub 图生视频、AI 情景视频。某类零镜头也输出合法空包。
- Shotcraft 只在实录字幕与 post-shoot 重绑完成后，对适用节拍逐项记录 `apply` 或 `not-needed`；拍摄前文稿不得冒充实录选择依据，选中但没有实际组件、帧段和应用回执时阻断候选验收。
- 建立九阶段生产状态机，禁止跳过素材门、实录重绑、低清候选和用户确认直接正式渲染。

## 保留边界

- 已发布的 GPT-6/Cybercab 成片和历史 revision 不返工、不覆盖。
- `workflow/active-production-profile.v1.json` 的 V8 正式生产基线保持不变，作为回退路线。
- V9 只对下一条新口播建立新 revision。必须经过真实素材端到端、低清候选、独立 QA 和用户正常速度观看，才能证明 V9 在正式生产中通过。
- RunningHub、付费、上传、公开发布仍按单次用户授权执行；Skill 升级本身不产生外部动作。

## 通过标准

1. 旧右下角人物位置被安全区验证器拒绝，V9 右侧安全槽和左侧回退槽通过。
2. 缺少逐物件/逐标签布局的 V9 纸艺请求在生图前失败；合法请求能生成三套相互隔离的提示词清单。
3. Shotcraft 选中但未落片时稳定失败；明确不用且有理由时合法。
4. 生产状态跳级、未看小样即开正式、未出正式即开发布包时稳定失败。
5. 导演 Skill 全量测试、活动导演档案校验、Skill 锁定和下一条合成 request 编译通过。
