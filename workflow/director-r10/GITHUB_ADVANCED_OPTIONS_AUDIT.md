# 导演系统 R10：GitHub 先进方案审计与采用边界

> 核查日期：2026-09-12
>
> 结论：现阶段不直接安装第三方导演 Skill。R10 先吸收“唯一语音时间轴、镜头生命周期、分段重渲、动态三重验收”四类方法；第三方代码与素材必须等当前旁路样片通过后，再做许可证、安全、依赖和视觉适配审计。

## 1. 最接近本项目问题的方案

### video-talkcraft

- 地址：<https://github.com/Vincentwei1021/video-talkcraft>
- 定位：专门面向口播/解说视频，以成品声音为时间权威，把语义拍写进分镜并由 Remotion 渲染。
- 当前公开能力：字级时间戳、约百张口播动效配方卡、反 PPT 镜头系统、分段重渲、音效逐 cue 检查、静止/抖动检测、锚点帧评审和浏览器工作台。
- 对本项目最有价值的不是卡片数量，而是：
  1. 动效锚定实际声音，而不是脚本或整段手填秒数；
  2. 镜头有入场、让位、动作完成和稳定状态，而不是只做一次卡片弹入；
  3. 改一个镜头只重渲该段及相邻段，避免每次整片返工；
  4. 机器检查静止、音效在场和锚点帧后，仍保留独立正常速度审片。
- 硬边界：仓库声明为 `PolyForm Noncommercial 1.0.0`，商业用途需事先授权。本项目面向公开账号与企业服务，不能直接复制其 Skill、代码或音效资产进入生产链。
- R10 决策：只独立实现同类工程思想，不复制受限实现；若以后希望直接采用，先取得商业授权并做供应链审计。

### video-shotcraft

- 地址：<https://github.com/Vincentwei1021/video-shotcraft>
- 定位：偏产品宣传片和真实页面演示，公开库包含大量镜头配方、运动预览、SFX 与浏览器工作台。
- 优点：仓库声明 Apache-2.0；镜头配方、2.5D 页面运镜、分段渲染和可编辑工作台成熟度较高。
- 不足：主要针对产品宣传片，不直接解决真人口播的实录字幕权威、中文节点、纸艺动作语义和本项目发布门禁。
- R10 决策：后续只把“分段重渲、镜头配方元数据、工作台轨道结构”列为可评估候选，当前不整包安装。

## 2. 可作为公共组件池的方案

### RemotionUI

- 地址：<https://github.com/riaz37/remotion-ui>
- 当前公开信息：约 200 个可复制源码的 Remotion 组件，MIT 许可，包含 primitives、scenes、data/media、compositions、transitions 等类型。
- 适合解决：基础过渡、字幕、数据图形、背景和路径动效的重复造轮子。
- 不能解决：选哪个组件、何时出现、是否贴合实录语义、是否越修越弱。这些仍必须由 R10 的时间轴、导演路由和动态质量门负责。
- R10 决策：旁路样片通过后，只按需审计并引入单个源码组件；不得用“库存 200 个”冒充本项目已验证 200 个效果。

### Onda

- 地址：<https://github.com/degueba/onda>
- 当前公开信息：MIT 许可、复制源码式组件、统一弹簧/时长/错峰参数和类型校验，强调克制而一致的运动语言。
- 适合解决：公共组件之间运动手感不一致、每个组件散落一套 easing 参数的问题。
- 不能解决：实录锚点、纸艺物件组、逐动作音效和本项目中文事实边界。
- R10 决策：把“统一 motion tokens + schema 作为组件 API”纳入 R10 组件注册表设计，不直接安装。

## 3. 官方 Remotion 基线

- Agent Skills：<https://github.com/remotion-dev/skills>
- 官方资源索引：<https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/resources.mdx>
- 官方字幕规则：<https://github.com/remotion-dev/remotion/blob/main/packages/skills/skills/remotion-captions/display-captions.md>

官方 Skill 适合规范 `Sequence`、`interpolate`、`spring`、媒体、字幕、音效和渲染做法，但它不是项目级导演系统。R10 继续以官方 Remotion 规则为底层实现约束，在其上增加实录权威、语义编译、组件生命周期、动态回归和用户验收。

## 4. 本轮立即采用的四项改造

1. **唯一语义运行时间轴**：字幕、画面与逐动作音效都从实录 caption/word 锚点编译，不再分别手填秒数。
2. **反退化组件合同**：复杂纸艺镜固定要求 5–6 个物件组、9–13 个中文语义节点、至少 3 层空间和 5–7 个装配节拍，并保留稳定停留。
3. **真实动态三重验收**：时间轴合同、真实媒体变化/冻结/边界、用户正常速度完整观看三层互不替代。
4. **分段重渲列入下一阶段**：当前先完成兰州 `40.0–97.9s` 隔离窗口；验证通过后，再把“改一镜只重渲该镜及相邻镜”接入正式制作，专门解决每次修复耗时过长。

## 5. 停止条件

- 第三方许可不允许当前商业使用；
- 必须修改现行 V8/V9.1 正式基线才能试用；
- 组件没有可运行源码、无确定帧行为或无法进入动态回归；
- 只增加组件数量，却没有降低迟到率、返工时间或纸艺退化率；
- 机器通过但用户正常速度观看仍认为迟到、PPT 化或纸艺质感下降。

命中任一项就不进入生产。第三方项目的星标、卡片数和演示视频只能作为调查线索，不能替代本项目真实样片。
