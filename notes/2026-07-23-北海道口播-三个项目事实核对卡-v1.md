## 二、今石缘

### 真实业务目标

今石缘的主体是线上赏石展，不是“观赏石海报生成工具”。当前要用一个线上流程完成石友招募、作品投稿、人工审核、入选展示、内容制作和后续传播，让今石缘从单纯的内容账号逐步形成石友交流平台。

### 完整业务链

```text
发起线上赏石展
→ 石友通过活动入口报名
→ 填写作品资料并上传图片，可选上传视频
→ 后台人工审核、补资料、编号并决定入选或暂缓
→ 已入选作品进入线上展厅
→ 根据真实资料整理赏析文案、海报和短视频素材
→ 由运营人员发布到群、朋友圈及今石缘账号
→ 完成人工评选、展播和数据复盘
```

### 当前已验证

- 现行 H5 技术方案明确核心链路为“报名 → 审核 → 展示”。
- 前端已有口令页、报名表单、图片上传、作品展厅和管理后台入口。
- 后端作品状态包含待审核、已入选、待定和未入选；公开列表只展示已入选作品。
- 运营方案明确由用户负责发布和最终决定，Codex负责整理、供稿和初审。
- 三张 AI 作品图属于作品入选后的内容制作子链，不是今石缘项目本身。

### 公开边界

- 可以说业务流程包含朋友圈、群和账号发布，但当前没有证据证明系统会自动发布。
- 当前代码证明的是后台审核和人工入选，不证明已经存在公众投票系统。
- 不得把线上赏石交流写成鉴定、估值、拍卖、保真或成交承诺。

## 四、大志设计灵感呈现

### 为什么要做

大志的问题不是“不会生成效果图”，而是他的灵感和判断产生得很快，可能来自旅行、现场勘察、短视频、参考图或客户沟通，但这些内容容易散落在记忆、纸面、聊天和文件夹里。过一段时间以后，灵感找不到，选择和修改的原因也留不下来，下一次项目又要重新开始。

长期目标也不只是提高一次出图速度，而是把大志的经验逐步沉淀为个人设计研发系统，让他从纯粹被动接单，逐步拥有按业态、面积、风格和经营目标组织的可复用设计方案库。

### 完整业务链

```text
捕获原始灵感、语音、文字、草图和来源
→ 保存并结构化为灵感卡和设计任务单
→ 生成三个真正不同的概念方向
→ 大志选择、修改并说明判断原因
→ 对选中方向连续细化
→ 可选生成概念短片
→ 把版本、选择理由和素材回写本地知识库
→ 以后按业态、风格、材料或客户问题检索复用
```

### 当前已验证

- 当前项目已进入 V1-B 内部真实验收。
- 一个付费匿名案例已经得到三张方向图、一张深化图和一条概念视频。
- 本地保存、检索、版本记录、连续细化、视频任务与重启恢复已有自动化验证证据。
- 当前首要验证仍是让大志用 3 至 5 个匿名真实项目判断方向是否有用、细化是否保留意图、输出能否进入真实工作。

### 公开边界

- 所有输出仍是 `concept_only`，不能作为施工图、BIM、准确尺寸、材料采购、造价或正式报价依据。
- AI负责理解、检索、生成、对比和整理；大志负责设计思想、审美判断、取舍和最终验收。
- 专业团队仍负责测量、深化、施工图、材料、造价、结构、机电和消防校核。
- 不能把“三个方向图已经生成”说成设计研发系统已经成熟交付。

## 五、上一版为什么会误读

1. 今石缘只读取了“三张海报 AI 升级状态”，没有先读取线上赏石展运营中枢和前后端主链。
2. 漫展只读取了“AI 模板预览”，没有先读取当前接管总览和票务、电子票、验票代码。
3. 大志只抓住“上传参考图、生成三个方向”这个可见输出，没有先读大志的真实痛点、知识闭环和设计产品化目标。
4. 内容门禁校验了来源是否存在、结构是否完整，却没有校验局部来源能否代表整个项目。
5. 跨项目上下文路由虽然已经建立，但写上一版时没有完成真实读取回执，旧的局部来源继续进入稿件。

因此，上一版不是简单的表达问题，而是“事实对象选择错误”。今后跨项目口播必须先完成以下顺序：

```text
当前项目身份
→ 项目级权威入口
→ 完整业务链
→ 当前代码与验证状态
→ 单个 AI 功能在业务链中的位置
→ 才能进入口播提炼
```
