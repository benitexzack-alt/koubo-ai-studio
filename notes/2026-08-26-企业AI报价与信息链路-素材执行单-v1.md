## 一、录制时采用的两处口径

1. 用户原稿“昨天几十家店数据要看”改为“昨天多家门店的数据要看”。现有资料能确认多门店、多周期数据问题，但不能独立确认公开表达中的具体门店数量。
2. 用户原稿“免费开源给需要的老板”改为“免费分享给需要的老板”。当前已经有真实工具包文件，但尚未建立公开代码仓库和开源许可证。

除这两处外，正文结构、观点和口吻不改。

## 二、你需要准备的素材

### R01｜真实录屏｜必需

- 文件名：`R01_信息获取作战平台_真实录屏.mp4`
- 放置目录：`02_真实录屏/`
- 建议时长：25 至 40 秒，可连续录制，后期按实录语义分段调用。
- 必须展示：
  1. 长期关注的来源入口或来源列表。
  2. 每天回来的候选信息。
  3. 从候选信息中筛选、标记或留下内容的过程。
  4. 后续做选题或项目时重新检索、调用已留下内容的过程。
- 隐私要求：录制前隐藏 API Key、手机号、客户名、聊天内容、财务数据、账号密码和内部地址。
- 画面要求：保持原始完整界面和鼠标操作，不提前裁成小窗，不加音乐，不加字幕。

### S01｜文生视频｜必需

- 放置目录：`03_用户生成视频/`

- 对应原句：“多家门店的数据要看……销售卖了多少，后端用了多少，库存还剩多少，东西散在好几个地方。”

## 三、不需要你制作的部分

以下内容由 Remotion 和现有真实素材完成，不再增加你的生图或视频工作量：

1. “便宜报价 / 高报价”不是结果对比，而是“买界面 / 理顺一段活”的透明信息卡。
2. 多门店、销售、消耗、库存、同行信号的分散节点与汇聚动画。
3. “数据从哪里拿 → 谁整理 → 谁判断 → 怎么执行 → 谁验收 → 是否继续”的六节点流程。
4. “AI负责收集、分类、对比、提醒 / 人负责判断、执行、承担结果”的责任分界卡。
5. 信息获取作战平台真实录屏的局部放大、鼠标跟随和语义旁注。
6. 餐饮、零售、服务三个行业标签。
7. “外部信号 → 客群 → 成本 → 供应 → 稳定性 → 小范围试验”的验证路径。
8. 结尾轻量工具包的真实文件展示和评论区关键词“信息”。

## 四、新版导演 Skill 的计划用途

新版纸艺编辑导演只用于两个抽象机制节点，不替换整条 V8 包装：

1. “一段活”六节点从散乱到接通的关系解释。
2. “热门信号”经过五项检查后进入小范围试验的条件路径。

当前只建立 `plan-only` 规划。原片到齐并完成实录转写后，才按真实时间点生成新的导演请求、完成态静帧和有声/无声候选；不得套用历史样片或旧任务时间轴。

## 五、V8包装原则

- 人物主画面始终是主体；信息层优先放在脸和手势对侧，局部覆盖不超过画面的 42%。
- 连续普通口播约每 8 至 12 秒必须有一次有意义的视觉变化，但不为凑数量堆卡片。
- 真实平台录屏优先于概念动画；情景视频必须标记为“AI生成·情景示意”，不能冒充真实企业证据。
- 中英字幕以实录语音生成；拍摄前文稿不能替换实际说法。
- 每个主视觉事件单独绑定非人声本地音效；禁用任何疑似人声、口令或旧的重复音效。
- 正式片前固定输出同画面 `WithSfx / NoSfx` 动态候选，正常音量人工确认后才允许继续。

## 六、原片到齐后的执行顺序

1. 原片和素材只读哈希、`ffprobe`、完整解码。
2. 按实录语音逐字转写，并与候选稿只做差异核对。
3. 用原句锚点绑定 R01、S01、S02 和 Remotion 信息卡。
4. 生成视觉方案、音效点位、风险帧和同画面有声/无声候选。
5. 机器质检后交本人完整观看；未经确认不渲染正式全片。
