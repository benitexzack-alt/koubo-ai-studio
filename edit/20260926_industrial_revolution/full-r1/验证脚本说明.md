# 全片技术检查脚本说明

脚本：`verify_audio.py`。输入媒体只读；唯一默认输出为本目录 `verify/技术检查.json`。脚本不修复媒体，不保存归一化音频，不安装依赖，不修改人工验收状态。

## 输入与计划

- 原音乐：`/Users/pc/Downloads/9月26日.mp3`。
- 最终候选：本目录 `exports/工业革命_从蒸汽到智能_三分钟_R2.mp4`。无声视频不能作为本脚本的通过对象。
- 制作 WAV：默认本目录 `public/music-full.wav`，实际命名不同时用 `--asset` 指定。WAV 未提供时会明确记录“未检查”，不会编造比较值；原曲与最终候选仍能直接比对。
- 视频计划：1920×1080，30fps，5412 帧，180.4 秒。
- 音频计划：原曲从 0 秒到 180.4 秒，播放速度 1，增益 -3dB，无淡入，末尾 0.12 秒淡出。

本机 `python3` 已有 NumPy，但没有 SciPy；脚本用 NumPy FFT 实现相关分析，避免新增安装。所需命令仍为现有 `ffmpeg` 与 `ffprobe`。

## 运行

```bash
python3 /Users/pc/Documents/口播/edit/20260926_industrial_revolution/full-r1/verify_audio.py --self-test
python3 /Users/pc/Documents/口播/edit/20260926_industrial_revolution/full-r1/verify_audio.py
```

如果制作 WAV 使用其他路径：

```bash
python3 /Users/pc/Documents/口播/edit/20260926_industrial_revolution/full-r1/verify_audio.py --asset /实际绝对路径/制作音频.wav
```

`--self-test` 仅在内存检查算法，不读取成片、不写技术检查报告。正常检查会计算完整媒体 SHA-256，解码全段音频与视频，因此应在封装结束后运行。报告绑定实际文件；成片后续被覆盖或重封装，须重新执行。缺文件会生成“待产物”报告，不能把该报告视为技术检查通过。

退出码：`0` 代表自检通过或本次机器技术检查全部通过；`1` 代表检查失败或存在未通过项；`2` 代表必要媒体尚未生成。必须同时阅读 `status`，不能把自检的退出码 0 当成成片通过。

## 检查内容

| 检查 | 方法与判定范围 |
|---|---|
| 规格与时长 | `ffprobe` 检查分辨率、帧率、帧数、容器/音视频时长；缺少帧数时实际解码计数；另外确认原音乐解码长度覆盖 180.4 秒 |
| 固定对齐 | 比较零延迟波形相关系数；必须至少 0.98，不能只在平移后高相关就声称原本对齐 |
| 最佳 lag | 22050Hz 单声道；FFT 搜索 ±0.75 秒，再逐样本细化；正数代表成片解码声音晚于原曲 |
| 封装起点 | 同时记录音频流与视频流 `start_time`；有效延迟等于最佳 lag 加上两流起点差，避免漏掉封装时间戳延迟 |
| 延迟标准 | 解码 lag、流起点差、有效延迟均须在 ±5ms 内；该标准用于发现此前约 42.676ms 的偏移，不是普遍适用于所有项目的标准 |
| 无明显漂移 | 六个分散的 12 秒窗口分别估计延迟；窗口间变化不超过 5ms，各窗口相关至少 0.97；只提供抽样证据 |
| 增益与淡出 | 原曲整体增益应在 -3dB±0.25dB；另构造计划增益与淡出的期望波形，记录末尾分窗能量；不独立反演任意混音包络 |
| 响度与真峰值 | 读取 `loudnorm` 的输入测量，处理输出丢弃；记录 LUFS/LRA/真峰值，真峰值不高于 -1dBTP；不强制改成 -16LUFS |
| 近黑候选 | `blackdetect`：最短 0.032 秒，黑像素阈值 0.08、比例 0.985；开头 1 秒和结尾 1.2 秒允许；仅完整落在 93.40–93.65 秒且回看证据哈希一致的事件分类为“已回看设计暗转场”；其他片中候选仍须回看，原始事件全部保留 |
| 文件稳定性 | 检查前后大小与修改时间须一致；检测期间文件变化不记为通过 |

主相关分析两端分别排除 0.25 秒与 0.35 秒，降低编码边缘和计划淡出的影响；尾段另列能量证据。单声道相关不单独验证立体声声像、相位或任何音乐版权。

## 机器证据与人工验收

报告始终把 `human_listening_performed`、`human_full_playback_performed`、`user_acceptance_recorded` 设为 `false`。只有实际人工完整观看、正常速度正常音量试听以及用户确认，才能另立验收记录；脚本不能把机器通过升级为人工验收。

若出现片中近黑候选，先回看指定时段判断是否符合分镜；不要直接放宽阈值或删除记录来制造通过。若全片尚不存在，本阶段只能说“脚本已自检”，不能说“全片技术检查通过”。
