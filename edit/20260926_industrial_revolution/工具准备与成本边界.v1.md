## 三、无需新增安装的建议路线

1. 用已有 React／Remotion 的原生 SVG、Canvas、图片与 CSS 静态样式构造画面；由帧号计算位置、缩放、旋转、景深与粒子状态。无需额外图形插件即可规划机械结构、时间轴、能源流动、电路和城市分层场景。[Remotion 基础原理](https://www.remotion.dev/docs/the-fundamentals)
2. 音乐先分析、再按乐段、重拍、铺垫和高潮编排镜头，生成固定到帧号的卡点表。`visualizeAudio()` 提供频段幅度，可驱动局部亮度、脉冲与粒子，但不是自动识别叙事章节或完成导演设计的工具。[官方音频分析](https://www.remotion.dev/docs/visualize-audio)
3. 音频数据加载使用现有 `useAudioData()`，其封装了等待加载后再渲染的流程。需要分窗分析时可使用现有窗口接口，但应按其输入格式要求实施，不能仅凭函数存在认定 MP3 可直接使用所有分窗路径。[音频数据接口](https://www.remotion.dev/docs/use-audio-data)
4. 所有动画由 `useCurrentFrame()`、`interpolate()`、`spring()` 与固定种子的 `random()` 驱动。避免使用普通 CSS 自动播放动画、真实时间累计和无种子随机数，防止跳帧与正式渲染出现不一致。[动画规则](https://www.remotion.dev/docs/animating-properties)、[确定性随机数](https://www.remotion.dev/docs/random)
5. 资源规划建议先以 1080p、低并发制作短段与代表镜头，再据实测决定完整渲染。16GB 内存条件下不宜在没有样片测量时承诺高并发全片复杂三维。这是规划建议，并非已完成性能测试。

卡点质量的证据应是正常速度播放时，音乐重拍、视觉动作落点和章节意义共同成立；频谱曲线存在、时间码相等或渲染成功只能证明相应技术事实。
