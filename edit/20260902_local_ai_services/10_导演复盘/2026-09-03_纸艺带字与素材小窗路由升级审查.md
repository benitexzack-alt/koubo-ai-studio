# 纸艺带字与素材讲解小窗路由升级审查

> 日期：2026-09-03
> 结论：升级到导演合同 v3.2；旧 R2 保留为历史证据，不覆盖。

## 一、已验证断点

1. 导演 R2 虽声明 RunningHub 使用 `*-text-baked.png`，但首帧生产批次没有保留 `deterministicTextBake`，也没有执行本地写字器。
2. RunningHub 提示词清单在带字图片与 OCR 回执尚不存在时就写成可提交状态，放行过早。
3. R2 所有镜头复用了同一组计划坐标，但实际生成图中的空白纸牌位置不同；直接写字会落错位置。
4. 现有路由把素材身份与呈现方式混在一起，只能表示“真实证据”，不能表示“素材主画面＋右下角真人讲解”。
5. 现有计划主要只有纸艺和真实素材两类，缺少 AI 情景演绎的明确触发边界，导致需要具体人物行为的画面被遗漏。

## 二、用户确认方向

- 纸艺首帧最终交给 RunningHub 时必须已经带有准确中文。
- 生成模型只负责无字纸艺基础图；中文由本地确定性工具写入并做 OCR。
- RunningHub 只做纸片滑入、平移、小角旋转、抽屉推出、展开底板和刚性拼图等动作，不负责写字。
- 讲解用户提供的真实视频时，真实素材占主画面，本人平滑缩到右下角继续讲解。
- 没有真实素材但确需人物、行为、环境或情绪时，AI 生成视频全屏播放，只作情景演绎。
- 纸艺继续负责因果、流程、结构、对照、层级和关系变化。

## 三、为什么“超级个体”的文字看起来对得上

1. 每个镜头不是先做一段通用纸艺动画再临时加字，而是先从对应口播中提炼 3—6 个短节点，让文字成为抽屉、纸牌、六边形模块或机械按钮本身。
2. 文字与物件关系一致，例如“模型 / 会员 / 教程”位于同一层，“商业判断 / AI理解 / 工具调用 / 质量标准”等围绕人物形成能力结构；观众静音也能复述这一镜在讲什么。
3. 图生视频以前，首帧已经明确了节点文字、层级和位置，后续动作只负责揭示、滑入、拼合和收束，所以文字不会与口播主题脱节。
4. 当时生成模型恰好把多数中文做对了，但这只是单批次效果，不能当作稳定能力。v3.2 保留同样的“文字即物件”导演方法，同时改用本地确定性写字与 OCR，避免乱码、漏字和下一批次漂移。

## 四、v3.2 路由

四种互斥主画面：`speaker`、`real-evidence`、`generated-video`、`paper-editorial`。
`remotion-information` 只作为章节、关键词、来源、风险说明和 CTA 叠加层。

真实素材是否使用右下角真人小窗，必须额外判断：本人是否正在解释该素材、时长是否至少 2.8 秒、右下角是否没有关键内容、字幕能否避让、素材授权与声音策略是否明确。

## 五、带字首帧闭环

```text
无字基础图
→ 无字图视觉检查
→ 按实际图片标定每张标签纸四角
→ 本地确定性写入中文
→ OCR逐字相等
→ 带字联系表人工确认
→ runninghub-ready-pack.v1.json
→ 用户手工提交RunningHub
```

动作提示词清单本身不再代表可提交。缺少带字图片、标定回执、OCR 回执或用户确认中的任一项，RunningHub 入口保持阻断。

## 六、画中画实现边界

- 权威口播原片始终是唯一人声来源。
- 右下角真人是同一口播视频的静音副本，默认圆形 296×296，距右 72、距下 188。
- 进入 16 帧、退出 12 帧，禁止硬切；字幕与人物框至少间隔 24px。
- 出现裁脸、不同步、双重人声、字幕遮挡或主素材关键信息被挡时，回退全屏真实素材或主播画面。
- 新能力先放在导演 Skill 的隔离组件中，不改写共享 V8 组件；每条视频仍需独立低清样片验收。

## 七、停止条件

- 把 AI 情景演绎当作客户、收入、需求规模、政府事实或交付结果的证据。
- 用纸艺代替用户已经提供的真实案例素材。
- 用 Remotion 屏幕浮层冒充纸面节点文字。
- 多镜复制同一套纸面坐标，或未看实际图片就写字。
- 带字纸片折叠、弯曲、卷曲、拉伸、翻面、重写或被强运动模糊破坏可读性。
- 未按拍摄后的实际口播重绑时间点就进入正式生产。
