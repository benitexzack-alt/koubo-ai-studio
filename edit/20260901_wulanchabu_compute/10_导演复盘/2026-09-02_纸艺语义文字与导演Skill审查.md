# 乌兰察布算力成片：纸艺语义、文字与导演 Skill 审查

> 审查日期：2026-09-02
> 审查对象：`乌兰察布算力_16x9_V8_R1_有音效_正式候选成片_v1.mp4`
> 审查性质：事故复盘与升级方案，不等于自动重剪、重渲或发布授权
> 当前结论：风格方向成立，但实录对位、质检证据和纸面文字合同存在结构性缺口

## 一、结论先行

这次纸艺画面的核心问题不是“纸艺风格不对”，而是三条链没有闭合：

1. **实录语义链不够严**：后拍重绑只检查一句话是否出现在整份转写里，没有检查每个视觉节点是否真的落在声明的起止时间内，导致部分镜头提前展示后文。
2. **文字空间链被写死**：现行合同禁止生成画面出现可读中文，并规定全部中文由 Remotion 后叠；成片实现又是固定屏幕坐标卡片，不是贴在纸面物件上的文字。
3. **质检证据链不够可靠**：旧的“十条视频中帧联系表”和若干 `Pxx_source-*.jpg` 与正式片实际读取的 P01-P10 不一致。直接解码正式源 MP4 后确认，成片没有此前误判的 P01-P07 循环串镜。

逐镜审查结果：

- 精确对应：5/10（P02、P03、P04、P05、P08）
- 部分对应：5/10（P01、P06、P07、P09、P10）
- 明显不对应：0/10

这里的“不对应”只评价纸艺插片与当下口播的语义关系，不推翻整条成片的真人口播、官方素材、字幕、音频和整体包装。

### 四方会审的共识与分歧

本轮由语义审查、视觉/文字审查、Skill 合同审查和反方制片审查四个角色独立复核，再以正式片实际读取的 MP4、权威实录和代码实现裁决：

- **语义审查**：5 段精确、5 段部分、0 段完全错题；P06、P09、P10 是最高优先级。
- **视觉审查**：文字本身准确，但固定六栏会制造左右归属错误、早于物件出现，并且会被 `.slice(0,6)` 静默截断。
- **合同审查**：现行合同只规定“谁负责文字”，没有规定“文字属于哪张纸、怎样跟随、怎样遮挡”。
- **反方制片审查**：本片可以作为已看过的候选保留，但不能把当前六栏实现复制成下一条的纸艺模板；应先做单镜 A/B。

对 P03、P08 的严格程度存在轻微分歧：从主题和物件关系看可判精确对应；从“静音能否看清最终状态变化”看仍有提升空间。因此本报告保留“精确对应”评级，同时把“输入-动作-输出可见”加入下一版硬门。

反方给出的 `P0` 只适用于“是否允许当前实现成为 Skill 默认模板”，不用于否定用户已经审阅并基本认可的整条成片。

## 三、为什么画面里没有真正的纸面文字

这是现行合同的预期结果，不是偶发漏字：

- 活动导演档案规定 `generatedReadableTextAllowed=false`；
- 中文的唯一所有者被规定为 `remotion`；
- 预拍编译器会拒绝允许生成中文的请求；
- 首帧和图生视频清单都只携带 `postProductionTextOverlay`；
- 当前成片用六个固定屏幕坐标渲染标签，没有纸面四角、透视、遮挡、光影或运动跟踪信息。

因此现有方案能保证中文准确，但视觉上更像“视频上压了几张信息卡”，无法形成“字就印在纸卡、路牌、箱体和节点牌上”的统一材质感。

## 四、文字方案对比

| 方案 | 中文准确性 | 与纸艺融合 | 运动稳定 | 风险 | 结论 |
|---|---:|---:|---:|---|---|
| 生成模型直接写中文 | 低 | 高 | 低 | 错字、乱码、漂移、变形 | 不建议作为正式默认 |
| 当前固定 Remotion 屏幕卡 | 高 | 低 | 高 | 与物件脱节、像 PPT 叠层 | 只保留给标题、来源与事实注释 |
| 首帧确定性烧录中文，再做图生视频 | 高 | 高 | 中 | 动画模型可能改字、漂移或重绘；需 OCR 门禁 | 只用于低运动、刚性纸牌的 A/B 候选 |
| **Remotion 透视跟踪纸面文字** | **高** | **高** | **高** | 需要纸面四角、跟踪与遮挡数据 | **建议作为工程默认候选** |

建议的原则不是“让生成模型自由写字”，而是把纸艺节点文字分成两种可测试的确定性方案：

1. 首帧先生成空白纸牌、路牌、卡槽和箱体标签面；
2. 对几乎不运动的刚性标签，可由本地确定性排版器把审核过的短中文烧进首帧，再要求 RunningHub 保持字形；
3. 对会移动、翻折或被遮挡的纸面，使用 Remotion 按纸面四角做透视跟踪，文字跟随物件并参与遮挡；
4. 对首帧、中帧、尾帧做 OCR 和视觉检查，发生错字、变形、漂移或错误遮挡就退回；
5. 数据、来源、法律边界和长句仍由屏幕级 Remotion 精确叠加，不烧进生成画面。

## 五、导演 Skill 的根因

### 1. 预拍配对只管提示词，生成后证据缺少稳定身份

现有编译器已经为提示词生成 `sceneId`、`pairId`、首帧提示词哈希、视频提示词哈希和 `pairSha256`。但是 RunningHub 导出后只剩下 `视频.mp4`、`视频_2.mp4` 这类通用文件名；素材入库和联系表没有始终以正式资产 SHA 和 P 编号生成证据。这次正式文件本身正确，但旧联系表已足以造成错误审查，说明证据链仍需加固。

### 2. 后拍重绑只做全文包含检查

现有校验把整份转写归一化后，只判断 `actualSpokenLine` 是否在全文中出现。它没有截取 `startSeconds-endSeconds` 对应字幕再检查，也没有绑定字幕段 ID、词级区间或语义锚点。所以“这句话在全片后面说过”也能通过当前门禁。

### 3. `textPlan` 缺少空间语义，候选实现还静默丢节点

当前 `textPlan` 只有：

- `nodeId`
- `text`
- `enterStageId`
- `position`

它没有说明：文字属于哪张纸、写在哪个四边形面、是否被物件遮挡、是否随纸片运动、持续多久、最大字数、是否必须 OCR。

候选实现也没有消费 `nodeId`、`groupId` 或 `enterStageId`，只按数组顺序每隔 7 帧把标签放到六个固定锚点，并使用 `.slice(0,6)`。这会同时造成：

- 标签与物件的左右归属错误；
- 后续概念早于纸艺动作或实录出现；
- 第七项以后的节点无提示丢失；
- 预拍计划中的物理/语义节点被压成 6 条文字，无法追溯哪些被合并或删除。

### 4. QA 检查了技术正确，没有检查“看懂了什么”

现有风险帧和机器 QA 能发现黑帧、裁字、冻结、音轨等问题，但没有把“关闭声音后，画面是否仍表达这一句”设为正式门禁，也没有检查文字与物件的空间归属、动作阶段和遮挡关系。

## 六、建议升级合同

### A. 文字所有权改成三层

1. `diegetic-node-label`：2-6 个字，写在纸牌或物件表面；默认使用透视跟踪纸面文字，低运动刚性纸牌可试验首帧确定性烧录。
2. `screen-title`：一句短标题；可继续由 Remotion 放在安全区。
3. `fact-source-caveat`：数字、来源、限制条件、长句；必须由 Remotion 确定性叠加。

不应把 `generatedReadableTextAllowed` 简单改成 `true`。建议保留模型禁止自由写字，同时新增：

```json
{
  "modelGeneratedReadableTextAllowed": false,
  "deterministicTextMayBeBakedIntoFirstFrame": true,
  "paperNodeScreenOverlayAllowed": false,
  "defaultPaperTextMode": "tracked-paper-surface",
  "allowedTextEmbeddingModes": [
    "first-frame-baked",
    "tracked-paper-surface",
    "screen-overlay"
  ],
  "screenOverlayAllowedRoles": [
    "caption",
    "source-label",
    "fact-source-caveat",
    "ai-disclosure"
  ]
}
```

每个纸面文字项新增：

```json
{
  "surfaceId": "paper-card-03",
  "anchorQuad": [[0.1, 0.2], [0.3, 0.2], [0.3, 0.35], [0.1, 0.35]],
  "maxChars": 6,
  "persistence": "stage-2-to-end",
  "occlusionOwner": "foreground-paper-strip",
  "ocrRequired": true,
  "motionConstraint": "rigid-surface"
}
```

每镜可读节点建议控制为 4-6 个、同屏最多 4 个、单标签 2-6 个字，硬上限 8 个字。禁止用斜杠把两个不同节点硬并成一条，也禁止以固定 `slice` 静默删除节点。

### B. 新增“生成后素材入库门”

每个生成视频必须绑定：

- `sceneId`
- `pairId`
- `pairSha256`
- 输入首帧 SHA-256 与感知哈希
- 输出视频 SHA-256
- 首/中/尾帧
- 预期物件组与动作阶段
- 人工或 Agent 语义评级

输出文件名至少使用 `P01__<pairSha前8位>.mp4`。通用文件名可以保留为来源名，但不能作为场景身份。

新增反串镜检查：把每段视频与全部 P01-P10 的预期画面做匹配；如果它更像另一镜，而不是声明镜头，直接阻断。所有联系表必须从正式绑定路径按 `sceneId` 生成，并在图下或伴随 JSON 写入每格 SHA，禁止依赖文件系统排序猜编号。

### C. 后拍重绑改成区间强校验

新增并强制：

- `actualCaptionIds`
- `anchorStartMs`
- `anchorEndMs`
- `semanticAnchorText`
- `alignmentStatus: exact | partial | mismatch`

校验器必须只在声明时间区间内检查实录，而不是全文搜索。任一 `mismatch` 阻断正式生产；`partial` 必须拆镜、缩短节点或获得本条人工例外。

再增加两层时序约束：

- 一个视觉主张不得比对应实录提前超过 300ms；
- 一个物件标签与其动作阶段的偏差不得超过 3 帧。

P09 这类 `AI训练师` 被替换成 `运维支持` 的情况，还要用实录词项差分直接阻断。

### D. 新增无声可理解性门禁

每个纸艺镜头在正常速度、关闭声音后由审查者回答：

1. 画面讲的对象是什么？
2. 发生了什么关系或变化？
3. 与当下口播是否一致？

只有三个答案都成立，才允许 `exact`。风格漂亮、动画流畅或技术解码通过，都不能替代这一步。

机械关系镜还必须提交三个证据帧：输入、动作、输出。最终状态没有发生可见变化时，不能靠标签把它补判为通过。

## 七、最小验证，不直接全局切换

建议先做一组 5-8 秒同镜 A/B/C：

- A：现有固定屏幕 Remotion 标签；
- B：首帧确定性烧录 3-5 个纸面短词，再做图生视频；
- C：Remotion 透视跟踪纸面文字。

优先用 P04“乌兰察布到北京”或 P08“算力到本地交付”测试，因为路径和节点清晰，最容易判断文字有没有帮助。

验收指标：

- 正常速度一遍看懂；
- 中文零错字；
- 首/中/尾帧 OCR 一致；
- 文字不漂移、不穿帮、不被关键物件遮住；
- 比当前方案更像纸艺世界内部的信息，而不是后压的卡片；
- 与实录区间达到 `exact`。
- 普通观众静音看一遍，能复述“输入-动作-结果”。

## 八、本条成片的处理建议

当前用户已表示成片基本没有问题，因此审查不自动触发重渲。

- 如果本条尚未发布且愿意修一次：不需要重排源片。最值得修的是 P06、P09、P10 的语义出现时点，以及 P07 被截掉的“人工复核”；文字嵌入可以留到下一条 A/B 后再启用。
- 如果本条已发布或决定不再改：保留当前片作为用户接受的历史版本，但不能把这次素材映射和文字实现登记为导演 Skill 的合格样板。

## 九、建议实施顺序

1. 先修“后拍区间与逐节点语义重绑”。避免画面对了主题，却提前十几秒展示后文。
2. 再修“纸面文字归属与动作阶段绑定”，并禁止 `.slice(0,6)` 静默丢节点。
3. 加固生成后素材身份和质检证据 SHA，确保联系表一定来自正式绑定资产。
4. 做一镜纸面文字 A/B/C，用户正常速度确认后再改默认合同。
5. 最后更新 Skill 文档、模板、编译器、校验器和回归测试。

在用户确认以上升级方向前，不修改共享 `koubo-remotion-director`、活动导演档案或正式生产工具。
