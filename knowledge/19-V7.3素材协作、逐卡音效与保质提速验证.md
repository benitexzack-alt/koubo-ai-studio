# V7.3 素材协作、逐卡音效与保质提速验证

> 状态：下一条口播实验规则，尚未晋升为锁定生产基线。
> 实验目标：不降低已验收的字幕、动效、运镜、音效和质检标准，解决素材路由错位、制作链路绕过提速器、主动效卡音效漏配三个问题。

## 一、本次复盘结论

### 1. Remotion 不应伪装成实拍或电影化视频

Remotion 的长处是确定性信息表达：标题、字卡、数据、列表、流程、时间线、证据旁注和动态导视。它可以做“信息动画”，但不应默认代替需要人物、场景、行为、空间和氛围的叙事视频。

从下一条开始，所有画面先分为四类：

| 素材类别 | 默认责任 | 使用边界 |
|---|---|---|
| 真实证据、项目录屏、现场、客户授权素材 | 用户提供，Codex 校验和合成 | 不用 AI 生成画面冒充证据 |
| 人物行动、场景演绎、氛围转场、空间镜头 | 用户按中文执行单生成或拍摄 | 优先交给即梦、Seedance 或其他真视频工具 |
| 数据、观点、步骤、对比、流程、引用 | Codex + Remotion | 必须是信息图形或动效卡，不宣称为实拍视频 |
| 主播长句、无外部素材的普通段落 | 主播画面 + 数字运镜 + 透明信息卡 | 不为了填满画面强行生成假场景 |

如果截止制作前用户生成视频仍缺失，只允许两种降级：

1. 回到主播画面，用透明信息卡承载。
2. 使用明确标注的“情景示意”信息动画。

不得悄悄用 Remotion 伪视频填补，并在素材台账记录降级原因。

### 2. 上一条提速失效，是执行绕过，不是提速器失效

V7.2 已经有 `workflow/jobs/*.production.json` 和 `tools/run-v72-production.mjs`，能做输入指纹、缓存、分段预览、风险帧、单次正式渲染和计时报告。

2026-08-02 “AI 时代，普通人真正不可复制的资产，是信任”这条未建立生产任务和计时报告，后续手工进行了多次资产渲染、30 秒预览、全长低清预览和正式渲染。因此只能确认链路被绕过，不能伪造精确的分阶段耗时。

下一条强制顺序：

```text
先建生产任务
→ doctor
→ 素材和字幕一次定位
→ prepare（代表性片段 + 风险帧 + 音频预检）
→ 修正唯一已确认问题
→ formal（仅一次 1080P WithSfx）
→ 机器质检
→ 用户完整观看
```

默认不再生成全长低清预览。只有存在删减、重排、大量字幕不确定或全片结构风险时，才允许全长低清预览，并写明原因。

### 3. 音效漏配的根因是“合同缺失 + 音色不足”

Remotion 可以用帧和 `Sequence` 精确定位音频，不存在“无法和卡片精准匹配”的技术限制。现有链路的真正问题是：

1. 视觉方案只有图层起止时间，没有每个主视觉单元真正的入场帧。
2. 音效表和视觉方案分开手填，没有稳定的事件 ID 绑定。
3. 旧校验只检查音效文件是否存在，没检查主卡覆盖率和同步偏差。
4. 本地 V2 只有 8 个独立音色。精确覆盖所有主卡在技术上可行，但直接重复会单调。

## 二、V7.3 实验合同

### 1. 每个主视觉单元必须声画绑定

V7.3 视觉方案中，每个主动效卡、数据主视觉、章节卡、证据卡、流程卡、媒体舞台和主转场必须声明：

- 唯一 `visualEvent.id`；
- 真实入场时间 `visualEvent.enterAt`；
- 是否为主视觉单元 `visualEvent.primary`；
- `sound.policy = required | optional | none`；
- `sound.role`、`sound.cueId`、`sound.offsetFrames`和 `sound.maxSyncErrorFrames`。

机器门禁：

- 所有 `primary=true` 的视觉单元必须 `sound.policy=required`；
- 除 `speaker-base / camera-only / subtitle-only / ambient-overlay` 外，其他可见信息或媒体单元不得通过 `primary=false` 逃避音效；
- 音效点必须用 `visualEventId` 绑定该单元；
- 实际音效帧与预期入场帧的误差不得超过 2 帧；
- 主视觉音效覆盖率必须为 100%；
- 一张主卡内部的每个小字、每个字幕不需要发声，避免吜吵。

### 2. 音色扩展先试听，后晋升

现有 V2 音效继续可用，但下一条预览要增加以下轻量变体：

- 轻卡入场 2 种；
- 列表勾选 2 种；
- 线条/箭头连接 1 种；
- 数字计数和落位 1 种；
- 媒体切入 2 种；
- 证据纸张/截图 1 种；
- 章节扫过和结尾确认各 1 种。

新音效只允许来自可追溯许可库或自制文件，每个文件保留来源、许可页、下载日期和哈希。先在下一条短预览中试听，用户确认后才能进入正式本地库。

### 3. 用户生成视频的执行单必须先于录制

需要用户制作的视频和图片，必须使用编号执行单，且每一项写清：

- 生成方式：文生视频、图生视频、文生图或真实素材；
- 对应口播原句和用途；
- 建议时长、画幅、镜头和运动；
- 完整中文提示词；
- 禁止项：不要字幕、不要 Logo、不要水印、不要伪造具体证据；
- 固定文件名和放置目录。

没有中文执行单或无法判断“生什么”的素材需求，不得交给用户。

## 三、下一条验证标准

1. 在创建任何动画预览前，已存在本条 `production.json`。
2. 叙事型 B-roll 不由 Remotion 默认代做；需要时已有编号中文执行单和用户交付素材。
3. 不再默认渲染全长低清预览，使用代表性区间和风险帧验收。
4. 正式 1080P WithSfx 渲染只有一次；如果重渲，计时报告必须记录原因。
5. 每个主视觉单元的音效覆盖率为 100%，同步误差不超过 2 帧。
6. 短预览覆盖本条用到的所有新音效角色，由用户确认听得见、不压人声、不单调。
7. 生产器输出完整 `timing-report.json`，没有报告就不得宣称提速。
8. 首次验证只记录真实数据：用户观察的历史区间为 2–3.5 小时，下一条以“原片到位→正式片机器质检完成”为统一计时口径，目标先验证能否稳定压缩到 90–120 分钟，不做未验证承诺。

## 四、晋升与回退

- 本规则先作为 `v73-media-sfx-speed` 实验，不修改已锁定 V7.2 正式母版。
- 下一条机器门禁全通过、用户完整观看认可且计时数据完整，才记为第一次有效验证。
- 连续三条无素材路由错位、无主卡漏音效、无质量回退，才讨论晋升全局基线。
- 任一试听新音效影响人声或产生听觉疲劳，立即退回已验收 V2 音色，但保留逐卡精准绑定和计时门禁。
