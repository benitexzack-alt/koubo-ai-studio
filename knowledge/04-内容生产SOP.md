# 内容生产 SOP

## 一、选题阶段

每条内容先填写：

```markdown
- 主题：
- 服务对象：
- 观众痛点：
- 这条视频只讲一个结论：
- 已验证事实：
- 待验证假设：
- 不能说的内容：
- 行动引导：
```

## 二、脚本结构

默认结构：

```text
3 秒钩子
→ 具体问题
→ 本地化观察或个人经历
→ AI 解决路径
→ 可验证的一小步
→ 单一行动引导
```

账号宣言类可用：

```text
我是谁
→ 为什么现在做这个账号
→ 服务谁
→ 以后讲什么
→ 为什么值得关注
```

企业服务类可用：

```text
本地老板常见问题
→ 过去做法为什么低效
→ AI 能先改哪一步
→ 最小落地方案
→ 需要什么资料
→ 私信/咨询引导
```

## 三、拍摄建议

- 一条视频只讲一个主题。
- 保持口语化，不背 PPT。
- 先录完整表达，不追求一次完美。
- 重要句子前后留 0.5-1 秒空白，方便剪辑。
- 尽量避免背景音乐直接录进原片。

## 四、后期流程

1. 复制原片到 `source/`。
2. `ffprobe` 技术检查。
3. 抽帧检查构图和画面问题。
4. 提取音频并转写。
5. 根据逐字稿做内容诊断。
6. 出剪辑策略，等确认。
7. 粗剪和响度处理。
8. 生成 `visual-plan.json`，先确认动效方案。
9. Remotion 制作数字运镜、局部动效片段、字幕强化和信息卡。
10. 成片确认后，Codex 交付 `3:4` 封面提示词；用户自行从成片中筛选关键帧截图，再用 GPT / ImageTo 基于真实帧做封面包装。
11. 导出预览。
12. 用 `node tools/validate-visual-plan.mjs <visual-plan.json>` 校验标题归属、时间冲突、素材路径和风险抽帧。
13. 技术质检和人工确认。
14. 导出正式成片，并填写 `workflow/releases/<发布记录>.json`。
15. 用 `node tools/validate-release.mjs <发布记录>.json` 实测成片规格、完整解码、双语同步、视觉方案和素材引用。
16. 用户完整观看确认后，才可把发布记录状态改为 `verified`。
17. 发布后 24 小时回填数据，并决定本条实验是保留、继续试验还是删除。

## 四点五、正式成片硬门禁

正式成片不是样片的简单高清导出。每条视频从“样片”进入“正式成片”前，必须通过以下门禁：

1. **当前最高模板基线门禁**
   - 正式成片必须使用项目当前已验证的最高生产模板。
   - 新片只能等于或高于当前基线，不能低于当前基线。
   - 若因时间、素材或技术原因需要降级，必须明确说明“会低于当前基线”，并取得用户确认。

2. **字幕时间轴门禁**
   - 剪过的视频，字幕禁止手工估时间。
   - 字幕必须由“词级转写时间戳 + EDL 输出时间轴映射”生成。
   - 手工字幕只能用于字词校正，不能作为正式成片的时间来源。

3. **视觉模块门禁**
   - 正式成片必须检查是否包含当前模板基线中的核心模块：数字运镜、顶部栏目、主题条、进度条、语义动效卡、字幕动效。
   - 缺少任一核心模块时，只能标记为“简版预览”，不能标记为正式成片。

4. **预览门禁**
   - 正式成片前必须先输出 20-30 秒预览。
   - 预览必须检查：字幕是否跟嘴、动效是否出现、卡片是否挡脸、整体观感是否达到当前基线。

5. **三重质检门禁**
   - 技术质检：分辨率、编码、音频、完整解码。
   - 字幕质检：抽查开头、中段、结尾，确认字幕与声音同步。
   - 视觉质检：确认当前模板核心模块存在，数字运镜自然克制，并且没有遮挡脸、字幕和关键信息。

只有全部门禁通过，并经用户最终人工观看确认后，才能说“成片通过验证”。

## 四点六、模板升级闭环

所有正式横屏口播以 `workflow/production-baseline.v1.json` 为当前生产基线，以 `workflow/upgrade-backlog.json` 为唯一升级待办。

- 用户的新参考、反馈和问题，必须先登记为一个带验收标准的升级任务，不能只停留在聊天记录。
- 已确认缺陷可直接修复并进入基线；审美或效果类想法先作为单条主实验，不能自动替换默认模板。
- 每个 `visual-plan.json` 必须声明每层的 `titleOwner` 和 `overlapGroup`；同一画面组最多一层拥有标题，避免全屏素材与信息卡重复表达。
- 每条正式片必须有发布记录，记录素材、模块、机器质检、用户确认、升级决策和发布后数据。
- 一个实验连续三条稳定使用，并得到用户确认或发布数据支持，才允许升级为下一版默认基线。
- 封面默认按照 `workflow/style-library/strong-title-tech-cover.v1.md` 输出 3:4 提示词；封面真实表现必须在发布后数据中验证，不能只凭审美直接固化。

## 五、发布后复盘

每条视频发布后记录：

- 发布时间和平台。
- 标题和封面。
- 完播率。
- 点赞、评论、收藏、转发。
- 有效私信数量。
- 是否带来企业咨询。
- 哪句话或哪个画面引发反馈。
- 下一条保留什么、删除什么、验证什么。
- 本条 Remotion 动效哪些进入模板库，哪些删除或降级。
- 下条视频需要新增或升级哪个动效组件。
