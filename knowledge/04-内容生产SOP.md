# 内容生产 SOP

## 一、选题阶段

每条内容先填写：

```markdown
- 主题：
- 服务对象：
- 观众痛点：
- 这条视频只讲一个结论：
- 已验证事实：
- 待验证假设：
- 不能说的内容：
- 当前账号学习卡路径与 SHA-256：
- 本条采用的实测学习 ID：
- 标题答案、真实证据和首个价值最迟出现秒数：
- 计划时长、单一核心问题与数据/证据理由：
- 主指标、辅助指标、观察窗口和可证伪假设：
- 获得感证据：
- 惊喜感目标与真实依据：
- 表达力验收方式：
- 感染力的真实经历来源或不采用原因：
- 行动引导：
```

四项质量特征按 `15-抖音精选内容质量验收.md` 建立 `douyin_quality` 卡。获得感和表达力是本账号默认主目标；惊喜感和感染力按真实材料决定。内部自检不等于抖音已经认定精选。

选题卡之前必须先建立 `performance_feedback`。真实账号任务读取个人知识库中的 `当前账号实测学习卡.json`，校验当前 SHA-256，并逐项兑现学习卡里的开头、时长和指标合同。复盘报告用于理解原因，学习卡用于机器执行；只读报告、不填反馈卡，不能进入提纲或写稿。

## 二、脚本结构

使用完整访谈、长视频、文章或参考口播做深度改编时，不得直接套用下面的默认结构。先运行 `source-essence-synthesis`，确认母命题、必保认知节点、论证链、纠偏账本和普通人三层所得达到 `ready-for-outline`；提纲覆盖全部必保节点并达到 `ready-for-draft` 后，再根据口播时长组织表达。

默认结构：

```text
3 秒钩子
→ 具体问题
→ 本地化观察或个人经历
→ AI 解决路径
→ 可验证的一小步
→ 单一行动引导
```

成稿后必须把四项质量目标逐一指回正文：

- 获得感：哪一句提供了新信息、机制、工具或可带走动作；
- 惊喜感：新角度是否由证据支撑，删掉夸张词后是否仍成立；
- 表达力：陌生观众能否用一句话复述唯一主张；
- 感染力：真实经历、冲突或感受来自哪里；没有真实材料时不强求。

`production` 阶段的 `douyin_quality.review_status` 必须是 `human-reviewed`。机器只核对记录是否完整，不能替用户判断内容是否真的清楚、有收获或有共鸣。

账号宣言类可用：

```text
我是谁
→ 为什么现在做这个账号
→ 服务谁
→ 以后讲什么
→ 为什么值得关注
```

企业服务类可用：

```text
本地老板常见问题
→ 过去做法为什么低效
→ AI 能先改哪一步
→ 最小落地方案
→ 需要什么资料
→ 私信/咨询引导
```

## 二点五、完整稿固定交付包

从 2026-07-30 起，每份提交用户审阅或确认的完整口播稿必须在正文后附带：

1. 一个抖音主标题；
2. 两个抖音备选标题；
3. 一份可直接复制的全中文 `3:4` 封面提示词。

标题和封面提示词继续受事实锁、`humanizer-zh`、`humanize-koubo-script` 和内容门禁约束，不能为了点击率添加正文没有回答的问题、虚构结果或夸大结论。

封面提示词固定标注任务类型为“真人截图合成”：默认使用用户从当期成片中截取并上传的本人真人图片作为唯一人物，保持五官、表情、衣服和姿态不变，只做背景、标题、光线和环境融合。提示词必须写清精确封面文字、构图、主题元素、光线、色彩、`3:4` 画幅和禁用元素，并且全部使用中文。

缺少任一项时，文稿状态为 `incomplete-delivery`，不能称为完整口播稿。

正式成片阶段在上述脚本交付包基础上继续补齐：从本条正式成片的本人真实口播画面中截取一张推荐封面人物图，并记录来源文件和时间点；复核或修订 `3:4` 封面提示词、主标题、两个备选标题；同时准备抖音发布文案和话题。六类内容必须随成片一次性交付，缺少任一项时，成片交付状态同样保持 `incomplete-delivery`。

## 三、拍摄建议

- 一条视频只讲一个主题。
- 保持口语化，不背 PPT。
- 先录完整表达，不追求一次完美。
- 重要句子前后留 0.5-1 秒空白，方便剪辑。
- 尽量避免背景音乐直接录进原片。

## 四、后期流程

1. 复制原片到 `source/`。
2. `ffprobe` 技术检查。
3. 抽帧检查构图和画面问题。
4. 提取音频并转写。
5. 根据逐字稿做内容诊断。
6. 判断是否需要内容剪辑：只有用户明确要求删除、压缩、重排、处理重录或口误时，才出剪辑策略、粗剪并等待确认。
7. 完整单条口播默认全量保留，直接做响度处理和高清兼容输入；词级转写继续作为字幕、语义卡和数字运镜的时间依据。
8. 生成 `visual-plan.json`；用户已明确指定 V4、数字运镜或既有视觉方向时直接执行，不重复设置粗剪门禁。
9. 若视觉方案中的指定授权素材确实需要透明抠图、低清图片修复或生成式 B-roll 升清，在 `ready-for-production` 后运行 `koubo-asset-prep`；证据截图、真人主口播和封面不进入该链路，输出先人工检查再引用。
10. Remotion 制作数字运镜、局部动效片段、字幕强化和信息卡。
11. 成片机器侧质检完成后，Codex 从本条正式成片的本人真实口播画面中截取一张推荐封面人物图，核对脚本阶段已交付的标题与封面提示词是否仍与最终内容、人物画面和素材一致；需要时只做事实安全修订，不重新另起一套风格。
12. Codex 一次性整理 `正式成片 + 推荐封面人物图 + 3:4真人截图合成封面提示词 + 一个主标题和两个备选标题 + 抖音发布文案 + 抖音话题`，并把路径、截取时间点和文本写入发布记录；缺项时不得称为完整交付。
13. 用户在外部工具中自行生成和选择封面；需要调整时，Codex 只修改提示词或检查用户回传图片，不接管生成流程。
14. 导出预览或正式成片；完整单条口播可直接输出成片，仍须由用户在发布前完整观看确认。
15. 用 `node tools/validate-visual-plan.mjs <visual-plan.json>` 校验标题归属、时间冲突、素材路径和风险抽帧。
16. 技术质检和人工确认。
17. 导出正式成片，并填写 `workflow/releases/<发布记录>.json`。
18. 用 `node tools/validate-release.mjs <发布记录>.json` 实测成片规格、完整解码、双语同步、视觉方案、素材引用和V8完整交付包。
19. 用户完整观看确认后，才可把发布记录状态改为 `verified`。
20. 发布后 24 小时回填数据，并决定本条实验是保留、继续试验还是删除。

除 24 小时复盘外，还应保留发布后 3 小时内、72 小时和 7 天观察窗口。早期信号与成熟结果分开记录；更新当前学习卡后，旧内容门禁卡因哈希变化必须重新校验。

## 四点五、正式成片硬门禁

正式成片不是样片的简单高清导出。每条视频从“样片”进入“正式成片”前，必须通过以下门禁：

1. **当前最高模板基线门禁**
   - 正式成片必须使用项目当前已验证的最高生产模板。
   - 新片只能等于或高于当前基线，不能低于当前基线。
   - 若因时间、素材或技术原因需要降级，必须明确说明“会低于当前基线”，并取得用户确认。

2. **字幕时间轴门禁**
   - 剪过的视频，字幕禁止手工估时间。
   - 剪过的视频必须由“词级转写时间戳 + EDL 输出时间轴映射”生成；全量保留视频直接使用词级转写时间轴并减去统一头部偏移。
   - 手工字幕只能用于字词校正，不能作为正式成片的时间来源。

3. **视觉模块门禁**
   - 正式成片必须检查是否包含当前模板基线中的核心模块：数字运镜、顶部栏目、主题条、进度条、语义动效卡、字幕动效。
   - 缺少任一核心模块时，只能标记为“简版预览”，不能标记为正式成片。

4. **预览门禁**
   - 正式成片前必须先输出 20-30 秒预览。
   - 预览必须检查：字幕是否跟嘴、动效是否出现、卡片是否挡脸、整体观感是否达到当前基线。

5. **三重质检门禁**
   - 技术质检：分辨率、编码、音频、完整解码。
   - 字幕质检：抽查开头、中段、结尾，确认字幕与声音同步。
   - 视觉质检：确认当前模板核心模块存在，数字运镜自然克制，并且没有遮挡脸、字幕和关键信息。

只有全部门禁通过，并经用户最终人工观看确认后，才能说“成片通过验证”。

## 四点六、模板升级闭环

所有新口播视频以 `workflow/active-production-profile.v1.json` 为当前唯一生产档案，并按 `knowledge/20-V8连续语义动效与可感知音效基线.md` 执行V8视觉与音效规范。`workflow/production-baseline.v1.json` 只保留通用技术参数、V7.2锁定母版回归和故障回滚能力；不得据此静默回退新视频。`workflow/upgrade-backlog.json` 继续作为升级待办。

- 每个新生产任务必须明确声明当前V8档案；生产器对所有命令强制校验，不再依靠可选实验字段触发。
- 如单条确需回退旧版，必须写入用户明确批准、批准时间、原因和适用范围；缺一项即停止生产。
- `formal`、`formal-audio`和`all`是会产出或改写正式文件的命令，必须先通过`tools/validate-production-command-gate.mjs`；`formal.enabled`不是`true`时必须在打包、指纹和渲染前拒绝，不得只把“锁定”写在任务备注里。

- 用户的新参考、反馈和问题，必须先登记为一个带验收标准的升级任务，不能只停留在聊天记录。
- 已确认缺陷可直接修复并进入基线；审美或效果类想法先作为单条主实验，不能自动替换默认模板。
- 每个 `visual-plan.json` 必须声明每层的 `titleOwner` 和 `overlapGroup`；同一画面组最多一层拥有标题，避免全屏素材与信息卡重复表达。
- 每条正式片必须有发布记录，记录素材、模块、机器质检、用户确认、升级决策和发布后数据。
- 一个实验连续三条稳定使用，并得到用户确认或发布数据支持，才允许升级为下一版默认基线。
- 封面自动化已停止。默认交付为一份可直接复制的封面生图提示词；用户自行生成和选图，项目不再维护四宫格、人物抠像、封面任务状态机或封面发布门禁。

## 五、发布后复盘

每条视频发布后记录：

- 发布时间和平台。
- 标题和封面。
- 完播率。
- 点赞、评论、收藏、转发。
- 有效私信数量。
- 是否带来企业咨询。
- 哪句话或哪个画面引发反馈。
- 下一条保留什么、删除什么、验证什么。
- 本条原先的数据假设是否被支持、被推翻或仍需更多样本。
- 哪一项可以写入当前账号实测学习卡，哪一项只能保留为单条观察。
- 本条 Remotion 动效哪些进入模板库，哪些删除或降级。
- 下条视频需要新增或升级哪个动效组件。
