- 中英文同窗字幕与词级时间轴；

- `WithSfx` 正式路由和本地音效 V2；

## 二、单一生产清单

每条视频只维护一份：

```text
workflow/jobs/<date>_<video-id>_v72.production.json
```

清单统一声明原片、渲染副本、字幕、视觉方案、音效点位、预览区间、风险帧、输出路径和缓存目录。不再由多条临时命令分别记住参数。

运行器：

```bash
node tools/run-v72-production.mjs <production-job.json> doctor
node tools/run-v72-production.mjs <production-job.json> prepare
node tools/run-v72-production.mjs <production-job.json> formal
node tools/run-v72-production.mjs <production-job.json> qa
```

只在修改公共模板、渲染链路或基线参数时，用锁定参考任务再跑：

```bash
node tools/run-v72-production.mjs workflow/jobs/20260730_cycle_assets_v72.production.json regression
```

## 三、日常最短路径

```text
素材和词级时间轴就绪
→ visual-plan 与 sfx-cue-sheet 一次定稿
→ doctor
→ prepare（有音效动态预览 + 完整分辨率风险帧 + 音频预检）
→ 只修预览暴露的问题
→ formal（只渲染一次 WithSfx 正式片）
→ 机器质检
→ 用户完整观看
```

默认不再生成无音效对照版。只有音色、音量策略、音效类型发生变化，或者故障排查、用户明确要求时，才做 `WithSfx / NoSfx` 同画面对照。

## 四、缓存与重用

缓存键由任务清单、生产基线、运行器和所有声明输入的 SHA-256 组成。

- 输入完全一致：复用预览、风险帧和已渲染中间件。
- 字幕、素材、组件、音效或方案任一变化：指纹变化，对应阶段必须重做。
- 禁止为了命中缓存而不声明新输入。

本轮实测：

- `prepare` 首次执行约 `99.7 秒`；
- 相同输入再执行约 `3.3 秒`；
- 378.8 秒正式片逐帧渲染约 `1237.5 秒`；
- 两遍响度处理约 `30.7 秒`；
- 正式片机器质检约 `33.2 秒`；
- 19 个风险帧和 6 个代表性音效点的基线回归约 `38.3 秒`。

这些是当前机器和当前项目的实测，不是下一条的时间承诺。下一条要以新任务的 `timing-report.json` 回填真实耗时。

## 五、质量回归门禁

已验收母版回归必须同时通过：

- 时长差不超过 `0.1 秒`；
- 19 个风险帧 `SSIM >= 0.99` 且 `PSNR >= 45 dB`；
- 音效窗口同时检查相关性、归一化误差和 RMS 能量比；
- 综合响度差不超过 `0.5 LU`；
- 真峰值差不超过 `0.3 dB`；
- 完整解码、近纯黑帧、分辨率、帧率、编码和音频采样率检查通过。

深色章节过渡不等于空帧。黑帧门禁使用 `pic_th=0.999`，只拦截接近全黑的连续画面。
