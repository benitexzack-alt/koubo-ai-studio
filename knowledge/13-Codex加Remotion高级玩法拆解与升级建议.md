## 二、技术核验

### 已验证事实

- Remotion 官方支持两类透明输出：用于剪辑软件的 ProRes Alpha，以及用于浏览器的 WebM Alpha。
- ProRes Alpha 的官方组合是 PNG 帧、`yuva444p10le`、ProRes `4444` 或 `4444-xq`。
- Remotion 支持通过 props、Schema 和 `calculateMetadata()` 把文字、图片、颜色、时长、尺寸和导出参数做成可配置项。
- 当前项目已安装 Remotion `4.0.484`，能支持上述能力。

### 需要保留怀疑的表述

- “一句提示词自动做出百万博主同款”是营销化表述。视频本身实际使用了详细参数、参考图、图像素材、反复预览和人工选择。
- 开场的“几百万播放量”案例没有在本片中给出可独立核验的数据链路，不应进入我们的对外口播或能力承诺。
- “3D 卡片”可能是 CSS 透视与 2.5D 变换，不代表必须引入真实三维引擎。对口播信息卡而言，可读性优先于三维真实感。

## 三、我们已经具备的能力

- 数字运镜、顶部 HUD、进度条、中英双语字幕、全屏 B-roll 和语义卡片已组合在主成片 Composition 中。
- 已有 `statement`、`compare`、`checklist`、`flow`、`metric`、`perspective`、`mind-map`、`keyword-pop` 和 `ocr-callout` 等节点类型。
- 已有 `visual-plan.json` 图层归属校验、预览门禁、双语同步检查和发布记录。
- 已有 OCR 定位与单帧验收的基础链路。

## 四、当前缺口与根因

1. **参数是数据，但还不是可验证的 Schema**  
   `Root.tsx` 只传入 `defaultProps`，没有绑定 Zod Schema；Studio 不能稳定提供可视化参数面板，错误参数也不会在渲染前被拦截。

2. **透明素材只写进规则，没有真正的交付链路**  
   项目文档已把透明贴片列为目标，但 `package.json` 没有 ProRes 4444 或 WebM Alpha 的渲染命令，也没有独立的透明 Overlay Composition。

3. **定尺寸布局没有文字溢出门禁**  
   `CardShell` 使用 `overflow: hidden`，`MindMapCard` 容器高度固定为 `244`，节点坐标又随索引继续下移。这就是上一条 OPC 卡片信息被裁切的直接根因。

4. **参考图只被记录，没有成为渲染合同**  
   现有视觉方案可记录参考素材，但组件层没有“参考特征 -> 原创变体 -> 验收帧”的强制对应。因此会出现“方案写了参考，成片还在用旧卡片”。

5. **有预览，但还没有完整的视觉回归循环**  
   当前依赖人工抽帧。没有按 `reviewAt` 自动渲染所有风险帧，也没有检查文字溢出、安全区和透明像素的机器门禁。

6. **生图工具和视频素材计划尚未形成统一素材清单**  
   现有 `tools/generate-image.mjs` 能生成图像，但没有在每个节点中固化用途、提示词、来源、版本、画幅、安全区和最终采用状态。

## 五、升级结论

**需要升级，但不是再安装一堆新 Skill。**

通用 Remotion Skill 已经包含透明视频、参数化、文字测量和单帧渲染等知识。当前主要矛盾是：这些能力没有被串进我们的日更口播生产线。

正确方向是建立项目专用 Skill：`koubo-remotion-director`，把通用知识变成我们每条视频必须执行的动作和验收门禁。

## 六、建议升级顺序

### P0：下一条 V4 正式片前必须完成

1. 建立 V4 原创组件：定义大字卡、三列能力卡、资源导向脑图、评论/案例浮层、行动输入卡。
2. 引入文字测量和溢出校验，禁止固定高度吞掉信息。
3. `visual-plan.json` 中每个参考素材必须绑定一个原创组件变体和一个验收帧。
4. 按 `reviewAt` 自动渲染钩子、每种 V4 卡片、全屏素材和 CTA 帧，通过后才允许渲染全片。

### P1：参数化与透明素材交付

1. 为高频卡片建立 Zod Schema，把文字、颜色、尺寸、节点数、动画时长和透明背景变成 Studio 可编辑参数。
2. 新增独立 Overlay Composition，同一组件支持“直接合成主片”和“导出 ProRes 4444 透明素材”。
3. 保留 WebM Alpha 作为浏览器预览选项，剪辑素材优先使用 ProRes Alpha。

### P2：素材生成与精确反馈

1. 生图/生视频提示词必须用中文按节点编号输出，并写入素材清单。
2. 所有修改意见绑定“版本 + 时间码 + 区域 + 问题 + 期望结果”，禁止模糊反馈。
3. 图像生成是按内容需要调用的素材能力，不得为了“看起来高级”每条视频强制生图。

## 七、升级验收标准

- 长标题、五个以上节点、中英字幕和极端文案测试下，卡片不裁切、不溢出、不挡脸、不挡字幕。
- 五种 V4 卡片在 1 倍速度下可读，箭头、节点和卡片使用帧驱动动画。
- 每个风险节点有实际渲染的验收帧，而不是只跑编译。
- 透明测试组件能输出 `.mov`，`ffprobe` 确认像素格式为 `yuva444p10le`，并能在透明棋盘背景上验证 Alpha 通道。
- 新能力先进入单条 V4 实验，连续三条稳定使用并得到人工确认或发布数据支持后，才允许提升为新生产基线。
