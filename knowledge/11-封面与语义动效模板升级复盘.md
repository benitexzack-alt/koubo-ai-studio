# 封面与语义动效模板升级复盘

> 日期：2026-07-04
> 适用范围：口播视频封面、视频内提示卡、后续 Remotion 模板升级。

## 一、这次解决的问题

旧版样片的问题不是功能没跑通，而是包装逻辑太单一：

- 封面只是“视频截图 + 蒙层 + 大字”，没有围绕每期主题形成视觉方案。
- 视频内提示卡只有一种信息样式，无法表达“判断、对比、清单、流程、指标”等不同语义。
- 生图 API 被当成“直接出最终封面”的工具，缺少失败兜底和素材替换机制。

v2 升级的核心不是单纯变好看，而是把口播包装拆成可复用生产链。

## 三、v2 模板升级内容

视频内动效从单一卡片升级为语义卡片：

- `statement`：观点/结论卡，适合反常识开场、账号定位。
- `compare`：对比卡，适合“错误路径 vs 正确路径”。
- `checklist`：清单卡，适合把老板经验、门店问题、客户反馈拆成条目。
- `flow`：流程卡，适合表达“经验 -> 表格 -> 话术 -> 选题库 -> 执行流程”。
- `metric`：指标卡，适合强调最小闭环、一个结果、一个验证动作。

封面从通用模板升级为主题模板：

- 增加 `coverKicker`，用于频道感和系列感。
- 增加 `coverBgSrc`，支持每期使用主题背景。
- 人物截图不直接硬贴，而是作为现场感图层，与背景、蒙层、标题系统融合。
- 3:4 封面优先服务抖音横屏视频信息流展示。

## 三点五、当前固定封面交付规则

从 2026-07-12 起，旧的“只交提示词、用户手动挑帧”规则停止使用，改为：

- 视频成片可以是 16:9 横屏，但封面固定按 `3:4`、`1080×1440` 输出。
- Codex 先从授权真实视频中选择四个不同时间点和自然表情，不使用 AI 换脸、补手或重绘人物。
- 每次先生成四张完整候选，并按 `1、2、3、4` 拼成 `2×2` 四宫格初稿。
- 四张围绕同一主题，但标题角度、人物表情、画面构图、背景氛围和颜色搭配必须全部不同。
- 用户选择编号前，不自行决定最终方案；用户选中后，只精修该方案并输出无候选编号的最终单图。
- 生图只负责无人物、无文字、无 Logo 的原创背景；中文标题和编号由本地程序化排版。
- 四宫格只说“初稿已生成，待选择”；最终单图只说“已生成，待人工确认”。
- 任务单统一保存到 `workflow/covers/`，渲染和校验由 `generate-koubo-cover` Skill 执行。

## 四、经验判断

1. 生图 API 不应该成为视频交付阻塞点。
   - 标准做法：先用代码生成可用占位背景，生图成功后替换。
   - API 失败时记录错误、保留命令和提示词，下次重试。

2. 封面不能只靠单次“自动截图”。
   - 原片如果人物离镜头太近，封面会显得压迫、暗、缺少商业感。
   - 每次必须抽取多个真实帧，用于四张候选的不同表情与手势；继续迭代脸部表情、清晰度、构图和文字安全区评分。
   - 更高阶做法是人像抠图：人物单独一层，背景单独一层，标题单独一层。

3. 动效必须跟语义绑定。
   - 讲判断时用结论卡。
   - 讲误区时用对比卡。
   - 讲方法时用流程卡。
   - 讲案例时用清单卡。
   - 讲结果时用指标卡。

4. 当前 v2 是样片升级版，不是最终商业封面标准。
   - 可用于内部评审和流程验证。
   - 正式发布前建议继续优化封面人物层、主题背景和标题文案。

## 五、后续模板系统方向

### 1. 选题到视觉的自动映射

每条视频进入制作前，先生成一份视觉方案：

```text
选题标题
-> 口播逐字稿
-> 语义段落 beats
-> 每段卡片类型 variant
-> 卡片文案/颜色/位置
-> 需要截图、真实照片、AI 背景还是数据图
-> Remotion 渲染
```

### 2. 素材调用规则

- 讲真实案例：优先放真实门店、产品、聊天记录、后台截图，敏感信息必须打码。
- 讲 AI 工具：优先放真实工具截图、操作界面、结果前后对比。
- 讲行业趋势：优先放可信信源截图、报告页、新闻标题，不直接编造数据。
- 讲方法论：优先用流程卡、清单卡、对比卡，不滥用 AI 背景图。
- 讲账号宣言：可以用 AI 背景和人物图层做强情绪封面。

### 3. 生图 API 使用边界

适合生图：

- 主题背景。
- 科技感流程视觉。
- 抽象概念图。
- 封面氛围底图。

不适合生图直接替代：

- 真实企业案例证据。
- 工具实际界面。
- 政策、数据、新闻来源。
- 用户或客户真实场景。
