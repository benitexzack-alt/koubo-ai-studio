# 实录优先字幕与系列发布包硬门禁

> 生效日期：2026-08-22
> 适用范围：本项目所有新拍口播、双语字幕、语义卡、V8 成片和抖音发布包。

## 一、事故与根因

《AI六层能力地图》正式候选片中，字幕时间窗来自原片，但字幕文字被后处理脚本压缩、顺句并向拍摄前文稿靠拢。结果是“时间大致同步，文字却不完全是实际说法”。

根因不是用户没有照稿念，也不是单纯的 ASR 错词，而是流程错误地把两种文本混成了一个事实源：

- 原片实际声音：用户真正说出口的内容；
- 拍摄前文稿：录制参考和核对材料。

以后两者必须分权，不能再由字幕脚本静默裁决。

## 二、唯一正文

拍摄完成后：

```text
原片实际声音 = 中文字幕唯一正文
确认后的实录中文 = 英文字幕唯一翻译源
拍摄前文稿 = comparison-only
```

即使用户没有百分之百照稿念，也必须按实际录音转写。字幕要保持实际用词、语序、信息量和句意，不替用户“说得更标准”。

## 三、允许与禁止

### 允许自动修正

1. 标点和合理断句；
2. 人名、地名、产品名等专有名词拼写；
3. 能由音频和上下文明确确认的 ASR 识别错误；
4. 中英字幕的同段同窗排版。

每项非标点修正必须记录原识别、修正结果、类型和依据。

### 未经用户批准禁止

1. 删除“就是、那么、其实、然后”等实际说出口的连接词；
2. 压缩一句话的信息量；
3. 调整语序或把两句合成一句；
4. 为了顺口改写语法；
5. 用拍摄前文稿补回用户没有说出的词；
6. 只改字幕、不改声音地纠正事实性口误；
7. 直接从拍摄前文稿翻译英文字幕。

## 四、口误与事实错误

如果实际声音里存在事实问题，固定流程是：

1. 实录转写先忠实记录；
2. 单独标记风险句和时间点；
3. 提供“补录、剪除、画面更正、整句保留”选项；
4. 用户决定后，同时处理声音、画面和字幕。

禁止把字幕改成另一句话，让观众看到的文字与用户实际说法不一致。

## 五、机器证据

每条新片建立 `spoken-source-policy.json`，至少记录：

- `canonicalSource=recorded-audio`；
- `scriptRole=comparison-only`；
- `captionTextPolicy=spoken-verbatim`；
- `englishTranslationSource=canonical-spoken-chinese`；
- 允许修正和禁止改写清单；
- 实录、字幕、原片路径；
- 校验状态和证据。

新片状态为 `passed` 时，必须运行：

```bash
node tools/check-spoken-source-policy.mjs \
  <实录转写.json> \
  <中英字幕.json> \
  <spoken-source-policy.json>
```

校验器同时检查全局文字保真和逐页时间窗贴合。只证明字幕文件内部一致、没有核对原始实录的旧校验，不再算“逐字通过”。

## 六、历史例外

已经渲染且用户明确接受不返工的成片，可以登记：

```text
known-exception-user-accepted
```

但必须同时满足：

- release 已绑定具体成片和具体 release ID；
- 用户已完整观看；
- 用户明确接受本期偏差；
- 记录偏差、原因和日期；
- 校验器输出警告；
- 例外不继承到任何下一条视频。

## 七、完整发布包触发器

有音效正式候选片一生成，立即建立完整发布包，不再等待用户追加索要：

1. 有音效正式候选片；
2. 从本条候选片截取的真人推荐帧；
3. 全中文 `3:4` 真人截图合成封面提示词；
4. 一个抖音主标题；
5. 两个备选标题；
6. 抖音发布文案；
7. 抖音话题；
8. 发布记录与双 Skill 审稿记录。

封面提示词固定从 `templates/10-超哥AI创业记_3比4系列封面提示词母版.md` 实例化。候选片未完成用户全片观看时，发布记录只能是 `ready-for-user-review`；用户终验后才可为 `verified`。

## 八、本期处理

《AI六层能力地图》当前成片已由用户验收，不返工。该条如实登记为“字幕存在非逐字已知例外，用户接受本期成片；规则从下一条严格执行”。不得把本期旧字幕反向包装成实录逐字校验通过。
