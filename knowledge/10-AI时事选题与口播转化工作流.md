# AI 时事选题与口播转化工作流

> 初版日期：2026-07-04
> 修订日期：2026-07-18
> 目标：建立“实时信息 → 来源资格 → 最近六条查重 → 机制解释 → 本人声音 → 口播脚本 → 镜头计划”的稳定流程。
> 上位规则：优先读取检测到的 `<personal-kb>/00_规范与配置/12_公开内容生产大脑硬门禁.md`；不存在个人知识库时，读取 `../skills/content-brain-gate/references/public-content-gate.md`。
> 账号定位：不是 AI 新闻搬运号，也不是把所有热点硬翻译成“本地老板做一个小动作”；而是把重要变化背后的机制、证据和真实影响讲清楚。

## 一、内容定位

账号内容由四类组成：

| 类型 | 占比建议 | 作用 | 典型形式 |
|---|---:|---|---|
| AI 时事解释 | 35% | 抓热点、获得推荐入口 | 3-5 分钟横屏口播 |
| AI 工具实测 | 25% | 建立能力信任 | 屏幕录制 + 口播 |
| 本地企业 AI 落地 | 25% | 形成差异化和商业线索 | vlog / 案例复盘 |
| 个人创业记录 | 15% | 建立真人 IP | 真实复盘 / 阶段总结 |

核心判断：

```text
热点负责入口，
工具负责信任，
本地案例负责差异化，
创业记录负责长期关系。
```

## 二、信息源分层

### A 级：一手来源

优先引用，适合做事实底座。

- 模型/产品官方博客：OpenAI、Anthropic、Google DeepMind、Meta AI、NVIDIA、阿里云、百度智能云、智谱、月之暗面、MiniMax、DeepSeek 等。
- 政策和行业数据：国家网信办、工信部、中国信通院、CNNIC、新华社、地方政府官网。
- 论文和开源：arXiv、Papers with Code、Hugging Face、GitHub Trending、模型官方 GitHub。

### B 级：国内科技媒体

适合发现选题，但需要回查一手来源。

- 机器之心
- 量子位
- 新智元
- 甲子光年
- 36 氪
- 钛媒体
- 智东西
- AI 科技评论

### C 级：平台趋势和创作者样本

适合观察表达方式，不直接作为事实证据。

- 抖音搜索和热点榜
- 小红书搜索
- B 站 AI 区/科技区
- 微信公众号爆文
- 同行业 AI 博主近期标题和封面

只有取得完整正文、字幕或用户提供的本地媒体后，才能拆原作者观点和 Talking 链路。只有标题、作者和链接时一律标记 `metadata-only`，只能作为选题线索。

### D 级：待核验线索

只作为线索，不直接公开。

- 群聊截图
- 朋友圈转发
- 未署名搬运文章
- 模糊来源的排行榜和报价表

## 三、每日选题流程

不设“每天 30—45 分钟必须完成”的硬时限。资料不够时宁可保持 `blocked`，不为更新频率强行写稿。

### 1. 收集 10 条候选

每条记录：

```json
{
  "title": "",
  "source": "",
  "url": "",
  "published_at": "",
  "source_level": "A/B/C/D",
  "raw_claim": "",
  "possible_local_angle": ""
}
```

### 2. 四项打分

每项 0-5 分，总分 20。

| 维度 | 问题 |
|---|---|
| 本地相关性 | 兰州/甘肃小微企业能不能听懂、用上、受影响？ |
| 可验证性 | 7 天内能不能用截图、实测或案例验证？ |
| 新鲜度 | 是今天/本周变化，还是旧知识换标题？ |
| 视觉化 | 能不能找到截图、网页、数据图、工具界面或现场画面？ |

分数只用于候选排序，不能代替来源资格、最近六条差异、机制卡和本人声音门禁。高分但与最近内容重复，仍然不拍。

### 3. 事实核验

公开口播前必须回答：

- 这件事发生在什么日期？
- 一手来源是谁？
- 媒体是否夸大？
- 有没有反方观点或限制条件？
- 对普通企业有什么“不能立刻推导”的地方？

### 4. 最近六条查重与第一性原理选题卡

先读取最近六条真实内容，逐条比较主张、证据、交付物和行动引导。再填写：

```text
服务谁，他此刻的具体问题是什么？
本条唯一新主张是什么？
与最近六条相比，新问题、新信息、新证据和新交付物是什么？
当前证据只证明什么，不能证明什么？
观众能带走什么判断、工具或行动？
哪些热点材料和产品不服务主张，应该删除？
```

本地场景只有在提供证据、影响判断或真实案例时才加入。不能为了强化人设，每条都强行转成兰州老板的小动作。

### 5. 核心对象机制卡

每个承担论证的产品、技术或案例必须讲清：真实问题、原有瓶颈、工作方法、可观察变化、证据、观众关系和不能外推的边界。

### 6. 口播结构

不再使用固定分钟数和固定段落模板。结构服从本条主张，优先从以下顺序取最少必要部分：

```text
一个反常识事实或具体问题
→ 纠正最容易听错的概念
→ 讲透一个机制
→ 给一手证据或必要案例
→ 说明与目标观众的真实关系
→ 给一个有边界的判断、工具或行动
```

不得先按“算力、模型、应用”或“第一个、第二个、第三个、第四个”凑展品清单，再为每个产品硬接普通人关系。

## 四、选题方向，不是固定公式

以下方向只能作为找题线索，必须通过内容大脑门禁，不能直接套话术。

### 方向一：一个被忽略的机制

```text
观众看到的是一个产品或新闻，
本条讲清它背后真正发生变化的瓶颈和机制。
```

### 方向二：纠正一个可核验的误解

```text
先写清流行说法，
再用一手来源、机制和边界纠正它。
```

### 方向三：真实实验或现场

```text
展示输入、过程、输出、人工复核和失败条件，
只得出实验真正支持的结论。
```

### 方向四：本地一手案例

```text
甘肃或兰州的真实项目、政策、机构、企业或行业材料
→ 解释它在更大技术变化中的位置
→ 说明适用与不适用边界
```

## 五、镜头机制

| 内容 | 画面 |
|---|---|
| 事实来源 | 官方网页/媒体截图，右上角标日期 |
| 机制解释 | Remotion 提示卡、流程图 |
| 本地翻译 | 真人口播 + 本地行业关键词 |
| 工具实测 | 屏幕录制、真实操作 |
| 线下案例 | vlog、门店外景、沟通现场、脱敏前后对比 |
| 结论动作 | 大字卡 + 1 个任务清单 |

## 六、标题方向

### AI 时事类

- `AI开始读懂那些从未被写成文字的世界`
- `一千张卡为什么不能简单堆在一起？`
- `这个新产品解决的，原来不是模型不够聪明`

### 工具实测类

- `同一份真实资料，三个模型到底漏了什么？`
- `我把输入和验收标准公开，看看AI能做到哪一步`
- `这次失败不是工具问题，错误发生在这里`

### 线下案例类

- `甘肃这个AI应用，真正接进了哪一段流程？`
- `同一个本地行业，AI能读懂的数据其实不一样`
- `现场跑完以后，这个结论我收回一半`

## 七、不可做

- 不用“震惊”“颠覆所有行业”等无证据标题。
- 不承诺获客、收入、排名和变现结果。
- 不把媒体二手报道当事实。
- 不未经授权展示客户隐私、后台数据、合同和聊天记录。
- 不把全国趋势硬套成本地结论，必须说明假设。

## 八、最小执行闭环

不按周强制凑“2+1+1+1”数量。每个候选必须依次达到：

```text
来源资格成立
→ 最近六条差异成立
→ 一个新主张成立
→ 机制卡完整
→ 本人声音已读
→ ready-for-draft
→ 事实锁/去AI味/朗读/合规/用户确认
→ ready-for-production
```

验收指标：

- 是否真正提供新问题、新信息、新证据或新交付物；
- 完播率。
- 评论里是否出现本地老板/创业者提问。
- 私信是否出现有效需求。
- 是否产生下一个线下案例线索。
