# 抖音精选内容质量验收

> 版本：2026-08-11
>
> 适用范围：准备在抖音公开发布的口播、访谈、案例、教程和项目复盘。
>
> 规则性质：这是内容质量目标，不是平台算法公式，也不保证作品一定被标记为“精选内容”。

## 一、来源与证据边界

本规则根据以下材料建立：

- 用户提供的抖音“精选内容特征”页面截图：`../refs/2026-07-23-抖音精选内容特征-用户截图.png`
- 抖音官方《抖音精选优质内容指南》公开页面：
  `https://www.douyin.com/video/7529857225054063913`

截图显示，用户喜爱的内容通常具有以下一个或多个特征：

1. **获得感**：知识、经验或见解兼具趣味和专业深度，表达深入浅出，让观众得到启发和收获。
2. **惊喜感**：选题、立意或表达有真实创新，与常见内容不同，让观众眼前一亮。
3. **表达力**：把想法、感受和信息说得清楚、准确、生动，让观众留下印象。
4. **感染力**：从真实体验和感受出发，真诚表达，触发共鸣。

固定边界：

- 四项特征是质量方向，不是抖音完整推荐算法。
- 具备一项或多项特征，不等于一定入选精选、获得流量或取得商业结果。
- 平台是否标记精选只能由平台决定，机器评分和项目自检不能代替平台结果。
- “公开发布、推荐搜索、精选内容、DOU+、广告交易”仍是不同门槛，不能互相推出。

## 二、口播账号的内部精品基线

抖音官方表述是“一个或多个特征”。结合本账号“本地 AI 实践者和复杂信息翻译者”的定位，内部采用更严格但不冒充官方的基线：

```text
获得感：主目标
表达力：主目标
惊喜感：按选题决定，可作主目标或辅助目标
感染力：有真实经历和真实感受时使用，不虚构情绪
```

每条稿件至少要把“获得感”和“表达力”设为主目标。原因不是平台强制，而是本账号首先要帮助观众看懂一个真实问题，并把复杂信息讲清楚。

惊喜感和感染力不能靠以下手段伪造：

- 编造客户、经历、收入、结果和情绪；
- 用极端标题替代新信息；
- 把局部功能包装成完整项目；
- 把可能、试验或方向说成已经成功；
- 用更强音效、卡片和画面掩盖内容空洞。

## 三、四项质量证据怎么填写

每条内容从提纲阶段开始建立 `douyin_quality` 质量卡。机器只能检查字段、证据和验收方式是否存在，不能宣布内容“有感染力”或“必然入选精选”。

`douyin_quality` 只回答“这条内容准备提供什么质量价值”；当前账号真实发布数据由 `performance_feedback` 单独回答。两张卡必须同时存在：不能用平台数据代替事实与质量判断，也不能用质量自评代替真实留存、主页访问和转粉结果。

### 1. 获得感

必须回答：

- 观众原来不知道、没想明白或做错了什么？
- 本条新增什么知识、判断、经验或工具？
- 哪一段真实证据支撑它？
- 看完以后，观众能完成什么判断或动作？

合格证据优先级：

```text
真实问题和现场
→ 一手来源或项目记录
→ 清楚的机制解释
→ 可带走的清单、判断或动作
```

“AI 很重要”“要落地”“坚持就会成功”不构成获得感。

### 2. 惊喜感

必须回答：

- 新意来自新问题、新证据、新机制还是新表达？
- 删掉热点名、产品名和夸张标题后，反差是否仍然成立？
- 这个反差是否可以被正文兑现？

以下不算惊喜：

- 只换标题和封面；
- 把常识写成“颠覆认知”；
- 用未经核验的数字制造冲击；
- 故意隐藏关键边界后再反转。

### 3. 表达力

必须回答：

- 全片唯一主张能否用一句话说清？
- 开头 20 秒能否让目标观众认出自己的具体场景？
- 每一段是否只承担一个意思？
- 抽象词后面是否紧跟人物、动作、输入、输出或结果？
- 标题、正文、字幕和画面是否表达同一件事？

表达力不是语速快、金句多或卡片多。准确、清楚、生动缺一不可。

### 4. 感染力

必须回答：

- 真实经历或真实感受来自哪里？
- 哪个矛盾、选择、失败或变化是本人真实经历过的？
- 去掉煽情形容词后，事实本身是否仍能触发共鸣？
- 是否给观众保留自己的判断空间？

没有真实体验时，可以把感染力设为辅助目标或非本条目标，不能补写一段虚构故事。

## 四、质量卡格式

新内容门禁卡使用 `schema_version: 5`，并同时填写 `performance_feedback` 与：

```json
{
  "douyin_quality": {
    "source_scope": "quality-guidance-not-selection-guarantee",
    "gain": {
      "target": "primary",
      "script_evidence": "正文中哪一段提供新信息、机制和可带走动作",
      "viewer_test": "目标观众看完后能复述或完成什么"
    },
    "surprise": {
      "target": "supporting",
      "script_evidence": "真实的新角度或反差在哪里",
      "viewer_test": "删掉夸张词后，观众是否仍觉得有新意"
    },
    "expression": {
      "target": "primary",
      "script_evidence": "唯一主张、具体场景和清晰结构在哪里",
      "viewer_test": "陌生观众能否用一句话复述本条"
    },
    "resonance": {
      "target": "supporting",
      "script_evidence": "真实经历、冲突或感受来自哪里",
      "viewer_test": "观众共鸣是否来自真实处境而非煽情"
    },
    "integrity_boundary": "哪些惊喜和情绪不能通过夸张、虚构或隐去边界制造",
    "review_status": "planned",
    "selection_not_guaranteed": true
  }
}
```

`target` 只能使用：

- `primary`：本条主要追求，必须在正文中有明确证据；
- `supporting`：辅助增强，不能抢走唯一主张；
- `not-targeted`：本条不强求，但必须写明原因和验收边界。

阶段要求：

- `outline`、`draft`：`review_status` 可为 `planned` 或 `self-reviewed`；
- `production`：必须为 `human-reviewed`，且用户已经确认脚本；
- 历史 `schema_version: 1` 至 `4` 卡不自动继承本规则，重新进入选题、写稿或制作时必须升级。

## 五、从写稿到发布的验收顺序

```text
事实、来源、项目对象和合规先通过
→ 明确本条的获得感与表达力
→ 决定是否需要惊喜感或感染力
→ 写稿并标出四项正文证据
→ 去 AI 味、大声朗读和本人声音检查
→ 用户人工判断是否真的有收获、清楚、真实
→ 才进入拍摄、动效、封面和成片
→ 发布后用真实数据和评论复盘
```

真实数据复盘必须回到 `performance_feedback` 声明的主指标、辅助指标和观察窗口。没有绑定当前学习卡，或只看发布后几小时的单点数据，就不能宣布质量目标已经被验证。

质量层不能反向放行硬门禁。事实错误、来源不足、对象错位、与最近六条重复或用户未确认时，即使画面和表达很好，状态仍然是 `blocked` 或 `ready-for-draft`。

## 六、发布后验证

发布前只能说“本条以获得感、表达力等为质量目标”，不能说“已达到抖音精选标准”。

发布后记录：

- 平台是否实际标记精选；
- 完播、收藏、转发、有效评论和主页访问；
- 观众能否准确复述唯一主张；
- 哪一句带来“原来如此”的反馈；
- 哪个新角度带来惊喜，是否出现误读；
- 哪段真实经历引发共鸣，是否有煽情或过度表达；
- 下一条保留、删除和重新验证什么。

连续三条只能形成阶段判断。没有平台标记和真实用户反馈时，不得把内部质量卡升级为“已经掌握精选内容公式”。
