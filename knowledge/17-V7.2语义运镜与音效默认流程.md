# V7.2 语义运镜与音效默认流程

> 建立日期：2026-07-26
>
> 当前状态：用户已完整观看并确认 V7.2 有音效正式片为当前最满意版本；该片已锁定为生产回归母版。

## 一、事故根因

V7.1 正片出现“数字运镜像没有、音效也没有”的原因不是单一参数错误：

1. 正式片明确使用了 `NoSfx` Composition，所以音效不是渲染丢失，而是默认决策错误。
2. 人物画面虽然有缩放和位移，但长段落通常只变化约 2% 至 3%，横移只有几像素；代码存在不等于观众可感知。
3. 旧音效版只调用两种声音，音量约 0.065 至 0.085，既缺少语义分工，也缺少最终听感验收。
4. 静态关键帧只能检查裁切和遮挡，不能证明运镜存在、音效可听或不盖人声。

## 二、后续默认路由

以后所有进入正式制作的完整口播，默认执行：

```text
词级时间轴
→ 语义段落和重点节点
→ V7.2 语义运镜
→ 本地音效 V2
→ 20 至 30 秒有音效预览
→ 动态画面和听感检查
→ 正式全片
→ 最终响度与真峰值处理
```

- `WithSfx` 改为正常生产候选。
- `NoSfx` 只保留为故障排查、听感对照和用户明确要求的降级版本。
- 用户要求以后都加音效，不能再因为上一版 A/B 没有确认而自动输出无音效正式片。
- 音效是否存在是默认规则；具体音色、音量和落点仍须通过当期预览调整。

日常生产使用统一运行器：

```bash
node tools/run-v72-production.mjs <production-job.json> prepare
node tools/run-v72-production.mjs <production-job.json> formal
```

阶段缓存、完整输入指纹和回归门禁见 `18-V7.2保质提速生产流程.md`。

## 三、语义数字运镜

数字运镜不做持续呼吸式循环，只在语义段落内完成一次明确动作：

1. 段落开始：约 1.0 至 1.8 秒内推进。
2. 重点句：稳定在强调构图，不反复抽动。
3. 段落结束：平滑回落，为下一段重新构图。

人物口播建议范围：

- 基础缩放约 `103.5%`。
- 重点推进约 `107.4%` 至 `108.4%`。
- 横向位移约 `6` 至 `28` 像素，以不切脸、不切头、不放大画质缺陷为前提。
- 一次主运镜对应一个语义段落，通常 6 至 12 秒；不能按每句话机械缩放。

全屏图片和视频：

- `cover` 素材约从 `102.5%` 推到 `108%`，随后稳定到约 `105.5%`。
- `contain` 截图约从 `101.5%` 推到 `105.5%`，避免裁掉界面边缘。
- 运动持续约 10 秒，不再沿用“6 秒后完全静止”的旧参数。

## 四、本地音效 V2

资产与许可：

- 原始文件、许可记录和 SHA-256：`assets/sfx/koubo-sfx-v2/`
- Remotion 调用目录：`remotion/public/audio/koubo-sfx-v2/`
- 当前来源：Mixkit 官方免费音效库。

固定语义：

- 章节切换：`section-sweep.wav`
- 卡片或素材进入：`card-slide.wav`
- 重点数字：`number-affirmation.wav`
- 流程节点：`node-select.wav`
- 界面确认：`ui-click.wav`
- 证据画面：`evidence-shutter.wav`
- 关键判断：`keyword-select.wav`
- 回到口播：`zoom-out.wav`

密度要求：

- 30 秒通常 3 至 5 个音效。
- 一个完整流程需要连续节点时，最多 6 个。
- 普通字幕、普通标点和每一个关键词都不配音效。
- 禁止夸张爆炸、掌声、撒钱声、网络热梗和持续提示音。

## 五、正式验收

机器检查：

- TypeScript 和 Composition 注册通过。
- 视频完整解码无错误，不出现黑帧。
- 最终响度目标约 `-16 LUFS`。
- 真峰值必须不高于 `-1.5 dBTP`；建议留到 `-1.8 dBTP`。
- 有声与无声版差分必须命中计划节点，不能只有编码底噪。

动态人工检查：

1. 正常播放时，人物推进能够被感觉到，但不能像突然放大。
2. 画面回落和段落切换不跳变。
3. 音效落在信息动作上，而不是落在半句话中间。
4. 音效不遮住辅音、数字、句尾和字幕阅读。
5. 只有播放预览通过，才能把参数用于完整成片。

静帧联系表只证明构图和溢出安全，不能替代以上动态检查。
